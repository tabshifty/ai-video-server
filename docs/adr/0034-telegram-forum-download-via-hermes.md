# Telegram 论坛下载沿用 Hermes 接收入口与后端下载服务

状态：已接受并实现（2026-11-09），尚未部署。

现有论坛推送通过 Hermes 投递，Hermes 的 Telegram 适配器已有长轮询及按钮回调。首版沿用当前 Bot，由 Hermes 按固定规则处理下载按钮，后端负责从已入库帖子读取 ED2K、操作者对应的操作记录及现有下载任务；Go 服务不为同一 Bot 另起长轮询，以免多个消费者争抢更新。具体机器鉴权及回调扩展点在实施阶段核实，不将 Hermes 的现有采集令牌直接视为下载授权。

选择沿用 Bot 而非另建 Bot，保留用户在现有推送会话中完成资源选择与接收回执的体验，代价是功能交付同时涉及仓库后端与仓库外 Hermes 扩展，需要分别部署和验证。下载按钮不经过对话模型决策；仅允许本人 Telegram 用户 ID 操作。按钮、资源列表和回执留在原推送会话；一帖可能包含多条媒体消息，按钮只挂文字说明消息。

Telegram 仅新增显式操作入口，共用网站的云下载任务、资源去重与失败恢复，不自动导入媒体库。多资源确认后的全帖下载是 Telegram 入口的显式批量行为，不改变架构决定 0029 中网站论坛页仍逐条下载的边界，也不复用工具箱来源标记。完整产品范围见 [首版设计](../telegram-forum-download-design.md)。
