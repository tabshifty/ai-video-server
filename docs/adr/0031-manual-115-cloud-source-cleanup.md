# 115 云盘源文件手动移入回收站

## 背景

115 云下载完成后，本地文件已经落在 `DOWNLOAD_DIR`，但 115 云盘里仍保留同一文件，持续占用网盘空间。管理员需要在本项目里对已完成的单文件任务显式清理源文件，而不是到 115 网页逐个查找。

当前云下载使用已登录的 115 浏览器（CDP），没有接入 115 Open Platform OAuth。115 云下载任务列表原始行包含三个不同含义的标识：

- `file_id`：任务源文件/文件夹 id，很多单文件任务里同时是云下载目录；
- `wp_path_id`：父目录 id；
- `delete_file_id`：删除任务源文件（夹）时应传给删除接口的 id。

受控测试在任务 10 上确认：`POST https://webapi.115.com/rb/delete` 使用 `pid=wp_path_id&fid[0]=delete_file_id&ignore_warn=1` 返回 `{"state":true}`，语义是移入 115 回收站，不是永久删除。把 `file_id` 当作 `fid[0]` 可能删错目录，因此禁止回退。

## 决策

- **手动、单任务、单文件**：只在 115 云下载任务列表对 `completed` 单文件任务提供“更多 → 移入 115 回收站”；不自动、不批量、不递归删除目录。`delete_file_id` 的 `file_category` 必须为 `1`（普通文件）才允许提交。
- **走现有 115 浏览器会话**：不新增官方 OAuth。同步调用已登录 115 页面的 web 删除接口，使用 `credentials: 'include'`；接口固定在 `https://webapi.115.com/rb/delete`。浏览器未运行/登录失效返回可操作错误，由现有二维码入口恢复。
- **只移入回收站**：不调用永久删除/清空回收站接口；不改变 115 回收站策略，不在本功能内恢复文件。
- **标识落库**：新任务在 `SetReady` 时保存 `cloud_file_id=delete_file_id`、`cloud_parent_id=wp_path_id`、`cloud_user_id` 和 `cloud_file_category`。历史任务按 `info_hash` 有界分页懒解析，必须唯一匹配，且文件名、大小和普通文件类型都与任务记录一致；解析不到、歧义或不一致时禁用删除。绝不把 `file_id` 当 `fid[0]`。
- **独立清理记录**：新增 `cloud_download_file_deletions`（`task_id` 唯一），记录 `file_id/parent_id/status/attempt/requested_by/error/note/timestamps`；状态为 `deleting/deleted/failed`。删除失败只改清理记录，云下载任务保持 `completed`，本地文件与导入记录不变。
- **显式确认**：前端从“更多”菜单打开确认框，展示任务记录的文件名/大小，明确“仅影响 115 云盘源文件，不会删除本地文件或导入记录，可在 115 回收站恢复，移入后不能从 115 重新下载”。API 要求 `{"confirm":true}`。
- **前置守卫**：任务必须 `completed`；本地源文件在 `DOWNLOAD_DIR` 内且为普通文件，或导入记录已终态 `imported/skipped_existing`（导入成功后本地源可能已被删除）；云文件标识必须是数字字符串；115 账号与任务创建账号一致（新任务）；浏览器会话必须已登录。活动导入不阻塞手动清理，清理也不等待导入。
- **幂等与并发**：`task_id` 唯一 + 原子 claim；并发第二个请求返回 409，不产生第二次 115 POST。`deleted` 重复请求直接返回；失败可显式重试；5 分钟未完成的 `deleting` 允许重新 claim。终态写库使用 `context.WithoutCancel` 和 attempt CAS，避免浏览器成功后请求取消把记录卡在 `deleting`。
- **115 成功语义**：仅严格 `state=true/1/"1"`、HTTP 200、错误字段为空且 JSON 解析成功视为成功；明确 `文件不存在/文件已删除` 的 JSON 错误可幂等记为 `deleted` 并带备注，父目录/HTML/未知错误必须失败；其他失败保留错误并允许重试。

## 考虑过的替代方案

- **接入 115 Open Platform OAuth 后调用 `/open/ufile/delete`**：更正式，但需要应用审核、OAuth 授权、令牌存储/刷新和新增配置；当前云下载整体是浏览器会话，首期不引入第二套鉴权。
- **下载完成自动删除**：会失去本地损坏/导入失败时的 115 回退源；用户确认先手动。
- **永久删除/清空回收站**：不可恢复且高风险；本 ADR 只移入回收站。
- **使用任务 `file_id` 作为删除目标**：在受控测试中 `file_id` 是父目录，会误删；必须使用 `delete_file_id` + `wp_path_id`。
- **历史任务无账号绑定时无限懒解析**：保留有界懒解析以兼容已完成任务，但无法证明历史任务一定属于当前 115 账号；这是已知残余风险，新任务通过 `cloud_user_id` 绑定。若后续要求严格，应关闭历史懒解析或先做账号回填。

## 后果与风险

- 新增 migration `0046_cloud_download_file_deletions`、清理记录表、`cloud:ingest` 之外的同步管理接口（不新增 asynq 队列）、任务列表清理摘要和前端确认框。
- 115 删除是私有 web 接口，不是官方契约；115 改版可能失效，且无删除专用频控说明。接口已验证一次“移入回收站”，但未覆盖全部 errno/账号切换/大量请求。
- 历史任务没有创建时的 115 账号快照；懒解析可能命中当前账号的同 hash 任务，存在跨账号误删的理论风险。新任务通过 `cloud_user_id` 拒绝账号不一致；首期以有界解析、文件名/大小/普通文件校验和人工确认降低风险，残余风险保留在 ADR。
- 5 分钟 stale 只表示“可以重新 claim”，不代表 115 端一定未删除；重试仍依赖 115 对不存在文件返回可识别错误，未单独做回收站只读核对。
- 导入成功后本地源文件可能已被导入服务删除，清理以导入终态作为“本地已有安全目标”的替代证据；如果导入目标后来又删除，本功能不会重新验证目标是否存在。
- 清理成功后任务仍为 `completed`，115 源文件在回收站；本地文件和导入记录不变。不会自动清空回收站，空间是否释放取决于 115 回收站策略和用户后续操作。

## 验证

- 受控测试任务 10：实际 `delete_file_id=3544176998614042374`、`wp_path_id=2726135308640032912`，`POST /rb/delete` 返回 `{"state":true,"error":"","errno":""}`，115 侧进入回收站；本地文件和本项目任务记录未改。该测试文件不恢复，作为已清理状态保留。
- Go 单测覆盖成功、幂等 deleted、浏览器失败记录、账号/目录拒绝、历史懒解析、导入终态放行、本地缺失拒绝、并发 409、115 not-found 幂等；前端覆盖确认框、状态、导入终态/超时重试、轮询和 API 契约。
