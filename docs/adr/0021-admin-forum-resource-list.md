# 管理端以只读论坛资源列表展示 Hermes 已纳入帖子

> 状态：已接受（2026-08-04）

## 背景

ADR-0020 已确定由 Hermes 负责论坛调度、抓取和筛选，项目后端保存帖子快照及附件、ED2K 资源。两阶段写入接口已经上线，但当时明确不提供读取和管理端展示。

管理员现在需要在项目管理端浏览 Hermes 判定为可用的论坛资源。这个入口用于发现和打开外部资源，不是采集任务监控、历史查重审计或下载工作台。现有数据库中还有通过 `dedupe_only` 导入的大量历史 tid，它们没有标题、帖子 URL 或资源，不能混入浏览列表。

## 决策

### 页面领域边界

- 页面命名为“论坛资源”，路由为 `/forum-posts`，位于管理端“服务与工具”分组。
- 列表只展示 `inspection_status='inspected' AND filter_decision='included'` 的帖子。
- `dedupe_only`、`pending`、`excluded`、`restricted` 和 `failed` 不进入该浏览投影；它们在资源感知保留策略允许的生命周期内仍作为采集事实保留，不因展示需求删除或改写。
- 页面严格只读，不提供编辑、删除、重新抓取、批量操作或资源状态回写。
- 继续使用 ADR-0020 的资源感知保留边界。读取查询限定 `created_at >= NOW() - INTERVAL '30 days' OR EXISTS (SELECT 1 FROM collected_forum_post_resources ... kind IN ('attachment', 'ed2k'))`：30 天内的已纳入记录全部展示，超过 30 天的记录只有仍有附件或 ED2K 时展示。即使 Hermes 暂停且请求触发的物理清理尚未运行，也不展示超期无资源记录。

### 管理员读取接口

新增管理员 JWT 保护的接口：

```http
GET /api/v1/admin/forum-posts?page=1&page_size=20
Authorization: Bearer <admin JWT>
```

接口沿用管理端 `{code, msg, data}` 包装：

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "items": [
      {
        "id": "4ae4c2f1-ff29-4b7a-a181-8a5c2336ad6f",
        "title": "帖子标题",
        "url": "https://sehuatang.org/thread-3670055-1-1.html",
        "attachments": [
          "https://sehuatang.org/forum.php?mod=attachment&aid=123"
        ],
        "ed2k_links": [
          "ed2k://|file|example.zip|1024|0123456789ABCDEF0123456789ABCDEF|/"
        ],
        "observed_at": "2026-08-04T10:30:00+08:00"
      }
    ],
    "total_count": 1,
    "page": 1,
    "page_size": 20
  }
}
```

- 默认页码为 1、每页 20 条，`page_size` 继续使用管理端公共上限 100。
- 按 `observed_at DESC, id DESC` 排序。发现时间表达论坛顺序；检查时间可能受抓取耗时或重试影响，不参与排序。
- 附件和 ED2K 分别按资源表 `position` 聚合。相同值不去重，确保读取模型与 Hermes 提交快照一致。
- 接口只返回页面需要的 ID、标题、帖子 URL、两类资源数组和发现时间，不暴露筛选原因、抓取方式、错误摘要或结果指纹。
- 读取接口不复用 `HERMES_API_TOKEN`；机器写入与管理员读取保持独立权限边界。

### 管理端呈现

- 使用管理端现有表格，一帖一行，列为“标题、文件链接、ED2K、发现时间”。
- 标题是指向帖子原始 URL 的 `<a>`，在新标签页打开，并设置 `rel="noopener noreferrer"`。
- 每条附件显示为“文件 1”“文件 2”……，按入库顺序在单元格内逐条换行；链接在新标签页直接打开原始 URL，悬浮时可查看完整地址。
- 每条 ED2K 使用数据库原始值作为 `<a href="ed2k://…">`，可见文本优先复用现有解析逻辑显示解码后的文件名，解析失败时显示原始值。
- 某一资源类型为空时明确显示“无”。资源重复时使用位置索引作为渲染身份，不按 URL 去重。
- 页面进入时加载一次，提供图标形式的手动刷新和服务端分页；首期不提供搜索、筛选或自动轮询。
- 首次加载、后台刷新、错误、空列表和分页切换使用现有管理端状态组件。长标题和链接在单元格内换行，窄屏时表格只在自身容器滚动，链接和刷新按钮保持至少 44px 的可操作高度。

### 原生链接与副作用边界

- 标题和附件由浏览器直接访问原始 HTTP(S) URL。后端不代理请求、不携带论坛 Cookie、不缓存附件；目标站点若要求登录，由浏览器中的论坛会话处理。
- ED2K 点击只交给浏览器和操作系统的协议处理器。页面不调用后端，不创建下载任务，不触发 115、本地暂存、媒体入库或转码。
- 页面不记录“已点击”状态，也不复用 ED2K 工具页的会话标记行为。
- 标题始终通过 Vue 文本插值渲染，不解释为 HTML；所有链接值来自已经通过 Hermes 写入接口协议校验的数据。

## 考虑过的替代方案

- **展示所有采集状态**：历史 `dedupe_only` 记录没有可展示内容，其他状态属于采集审计而不是资源浏览，拒绝混入首期页面。
- **所有浏览记录永久保留**：会让无资源的历史查重基线持续增长；本次只允许仍有附件或 ED2K 的记录跨过 30 天进入浏览投影。
- **把资源放入“媒体库”**：论坛链接尚未进入项目媒体库，放入该分组会暗示已经下载或入库，改放“服务与工具”。
- **把每条资源拆成独立表格行**：会重复帖子标题并破坏帖子聚合边界，采用一帖一行、资源作为子项。
- **前端去重**：会让页面与不可变采集快照不一致，拒绝采用。
- **后端代理附件或恢复下载工作台**：会引入站点登录态、缓存和下载状态机，违反既有职责边界。
- **自动轮询**：Hermes 每 15 分钟采集一次，浏览页没有实时监控需求，采用手动刷新。

## 后果与风险

- 不需要 migration，旧二进制和现有 Hermes 写入协议均不受影响。
- 超过 30 天且没有附件或 ED2K 的帖子会从页面消失；仍有资源的帖子不因年龄消失，该页面可以浏览被策略保留的旧资源，但仍不是无条件的历史归档。
- 附件能否打开取决于目标论坛可用性和浏览器登录态，项目后端无法保证。
- ED2K 能否拉起客户端取决于访问管理端的设备是否注册对应协议处理器。
- 当前资源数据量有限，读取时复用 `created_at` 索引和资源表的帖子关联索引即可；若未来扩大来源数量或资源保留规模，应基于真实查询计划再评估复合索引，而不是提前增加 migration。
