# 115 本地暂存显式删除

## 背景

115 云下载完成后，文件已经落在 `DOWNLOAD_DIR`，任务行保持 `completed`，等待管理员显式导入媒体库。实际使用中管理员会在下载后才发现资源已经在库里（重复资源），此时既不会导入，也不会触发“导入成功后顺手删除本地源文件”的既有行为，几 GB 到十几 GB 的本地文件会永久留在下载目录。

现有两个删除动作都不覆盖这个场景：

- [[115 云下载导入]]：只有真正提交导入，才会在成功/跳过时删除本地源；
- [[115 云盘源文件清理]]：只处理 115 云盘那份，且前置条件要求本地文件仍在或导入已终态。

因此需要一个显式的“删除本地暂存”动作，并且它必须和“115 下载已完成”这个事实正交，不能改写任务状态语义。

## 决策

- **只删本地、单任务、显式**：新增 `POST /admin/cloud-downloads/:id/local-file/delete`，只删除 `DOWNLOAD_DIR` 内的本地文件；不删除任务记录、不删除导入记录、不改动 115 云盘源文件；不自动、不批量。删除前用 `GET /admin/cloud-downloads/:id/local-file` 展示路径、实际大小与存在性。
- **状态保持 `completed`**：删除本地文件不改变“115 已下载完成”的结果，因此任务状态机不变；新增 `local_file_deleted_at` / `local_file_deleted_by` 记录清理事实，列表显示「本地已删除」并停用导入入口。`local_path` 保留作为历史。
- **守卫**：任务必须 `completed`；活动导入（`queued/hashing/copying/creating`）拒绝（409）；`failed` 导入允许删除但确认框提示无法再重试；`failed/blocked/进行中` 不开放。
- **幂等与路径安全**：路径必须解析在 `DOWNLOAD_DIR` 内（拒绝 `..`、符号链接逃逸、目录与非普通文件）；文件已不存在视为幂等成功并补记删除时间，避免陈旧记录无法清理；空 `local_path` 返回明确错误，不伪造清理事实。
- **确认**：API 要求 `{"confirm":true}`；前端确认框明确“仅删除本地暂存文件，不删除任务记录，也不影响 115 云盘原件；删除后不可恢复且无法再导入媒体库”。
- **不放宽为“可重新下载”**：`info_hash` 全局唯一且 `completed` 任务再次提交会被跳过，误删无法通过重新提交找回；v1 不提供重新下载，确认框明示不可恢复。
- **放宽 115 回收站前置条件**：本地文件被显式删除后，「移入 115 回收站」不再要求本地文件存在或导入终态，否则“先删本地”会让云端那份永远无法清理。该组合下 115 云盘是最后一份副本，确认框追加提示“本地与 115 均无可用副本（可在回收站恢复）”。

## 考虑过的替代方案

- **硬删任务记录**：列表更干净且能重新提交，但会丢失导入/清理关联，并让 115 云盘文件失去删除入口；不采用。
- **删除本地同时移入 115 回收站**：一次清干净，但把离线可完成的本地删除与依赖 115 登录会话的远端动作绑在一起，失败模式耦合；保留为两个独立动作。
- **删除后提供“重新下载”**：需要把完成任务重置为 pending 并再次触发已完成的 115 任务，依赖未验证的 115 行为与状态机改动；v1 不做。
- **自动识别重复并删除**：管理员是显式判断“资源已有”的人，自动判定需要可靠的媒体去重语义（压缩包内容无法按单文件哈希去重）；不采用。

## 后果与风险

- 新增 migration `0051_cloud_download_local_file_deletion`（两个可空列）与两个管理端接口；不改 asynq 队列与 worker。
- 删除是不可恢复的本地操作；误删只能重新获取资源（当前无重新下载入口）。确认框与 409/410 类型化错误承担主要防护。
- 导入创建与本地删除之间仍有 check-then-act 窗口：活动导入校验通过后、导入记录落库前删除文件，会让导入以“源文件不可用”失败。文件本来就是要删除的，不会损坏媒体数据，但“活动导入必 409”在边界上不绝对；后续若需要严格互斥，应在两条路径对同一任务行加锁。
- 本地删除后 115 云盘可能成为唯一副本；这是管理员显式选择的结果，回收站可恢复。
