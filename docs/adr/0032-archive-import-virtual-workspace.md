# 压缩包入库整理采用独立的虚拟目录与分组关系

2026-10-26，用户确认压缩包上传后使用全屏工作台：左侧模拟文件管理，右侧维护可继承的入库分组。整理过程需要反复改名、移动和分组，同时原有物理文件必须保持不变，因此虚拟目录、入库分组和源文件位置分别表达；按目录生成分组只建立初始层级，之后两棵树独立维护。相比直接修改解压目录或让分组始终绑定目录，这允许管理员整理入库关系而不破坏源文件定位，也不会因左侧目录调整而静默改变右侧默认值。

每个文件最多归属一个分组，同组允许混合媒体；拖拽只修改可自动保存的批次草稿，管理员显式提交后才进入正式媒体库。虚拟名称、分组配置与正式媒体分别具有自己的生命周期，不能因为批次草稿发生变化就推定已入库实体也需要同步修改；提交后的具体编辑边界已在后续确认中明确。本记录确认领域边界，数据库结构、草稿并发策略和历史数据迁移尚未定稿。

第二轮用户确认：成功文件的本次入库配置冻结，分组默认值变化只作用于未入库成员；命中库内已有内容时复用媒体并追加合集关系，保留原标题、说明、标签及历史关联。这明确区分“保存整理草稿”“把文件入库”和“编辑正式媒体”，避免一次批次整理覆盖其他来源已建立的媒体关系。旧批次保留原整理结果，重解压只允许尚无成功文件的批次并要求确认重置；本次仅改管理端与后端，手机和 TV 多图片合集展示另行交付。

第三轮用户确认主分组就是上传时填写的内容。成功文件禁止换组和排除，含成功成员的分组及祖先不能删除；新流程统一通过图片合集建立关联，不再生成同目录逐图片直接关联。选择合集关系作为后续入库的关联表达，避免同时维护两套可自动生成但展示语义不同的关系；历史直接关系保留，避免重构过程破坏既有数据。

第四轮用户确认：主分组是当前批次唯一且不可删除的根节点，根目录文件直接归主分组，普通组及独立未分组回退区均以主分组作为最终默认值来源。入库提交固定成员与配置，由后台持续执行，页面关闭或后续草稿修改不改变本次执行内容；处理中成员锁定，其余文件仍可整理。这使草稿保存、入库执行和正式媒体编辑具有明确边界，同时要求实现提供可恢复状态与冲突保护，具体技术机制在实施设计中确定。
