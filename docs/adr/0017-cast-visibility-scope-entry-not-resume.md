# 投屏可见性只约束目录展示与发起，不约束已发起会话补页

"可见短视频合集"（active 且至少一条可播放）约束的是手机端合集目录展示与发起投屏；它不约束 TV 端已发起投屏会话的补页。合集投屏会话一旦建立，TV 端补页只按 `collection_id` + 视频 `status='ready'` 过滤，合集中途被管理员停用不中断已开始的投屏。

## 考虑过的备选

- **B 补页也检查合集 active**：合集停用则补页返回空、投屏在已加载页放完后停止。被否：用户中途被打断体验差，且与"会话已建立"的契约感弱。
- **C 合集停用后端主动结束该投屏会话**：被否：需要后端监听合集状态变更或会话拉取时校验，复杂度高，超出本轮范围。

## 后果

- active 的语义边界是"入口维度"：管"能不能开始投"，不管"已投的能不能放完"。这与搜索投屏既有行为一致（搜索结果视频被删/下架，已发起的投屏不主动中断）。
- 已加载页的 items 是投屏瞬间快照，照常放完；补页拉来的新视频按后端实时状态，删了下架的自然不再出现，不报错、不中断。
