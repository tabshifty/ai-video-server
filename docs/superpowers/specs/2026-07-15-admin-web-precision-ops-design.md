# PC 管理端 Precision Ops 样式升级设计规格

## 1. 文档状态

- 状态：已确认
- 确认日期：2026-07-15
- 适用范围：`admin-web/`
- 目标平台：PC 管理端优先，保留现有窄屏可用性
- 技术栈：Vue 3、Element Plus、ECharts、Vue Router、Pinia

本规格只定义设计方向、交互边界、推广顺序和验收标准，不包含业务代码实现。后续实施计划必须逐项覆盖本规格，不能把样式升级扩展为路由、权限、接口或业务流程重构。

## 2. 背景与现状

管理端已经完成第一轮 Modern Minimal 改造，现有基础包括：

- 浅色 slate 中性色与冷蓝主色。
- 固定侧栏、窄屏抽屉、侧栏折叠偏好。
- 分组导航与 `Cmd/Ctrl+K` 命令面板。
- `theme.css` 设计 token、`element-overrides.css` 全局覆写和 `components/base/` 基础组件三层架构。
- `PageHeader`、`Toolbar`、`SectionCard`、`StatCard`、`EmptyState`、`BulkActionBar` 等共享组件。
- 视频列表列设置、图片网格/列表偏好、筛选 chip、详情 Drawer 和批量操作等效率能力。

因此第二轮升级不是换一套皮肤，也不是推倒重写。真实页面核对发现的主要问题是：

1. 普通页面自行渲染 `PageHeader` 后，壳层仍保留 64px 顶栏，只显示右侧快速跳转，形成一整条低价值空白。
2. Dashboard 使用 8 张同权大卡，运行信息、内容库存和次要统计没有优先级，首屏纵向占用过大。
3. TaskMonitor 同时存在状态按钮、标签、4 张统计卡和任务表，信息重复；4 张卡落入 3 列网格，且当前页成功数除以全局总量得到的“成功率”口径错误。
4. VideoList 的 96×54px 封面和 300px 操作列压缩了可比较字段，详情、重转码、删除三个按钮长期占据横向空间。
5. ImageManage 网格卡最小宽度为 220px，1440px 首屏资产量偏低；卡片操作默认透明，只靠鼠标 hover 出现。
6. 侧栏媒体库分组较长，在常见高度下需要滚动才能看到服务、工具和系统入口。
7. 多数页面视觉整洁，但卡片、空态和区块留白偏舒适，不符合高频 PC 管理工具的扫描与批量处理需求。

管理端当前约有 18,903 行 Vue 视图代码，其中 `ToolboxArchiveImport.vue`、`VideoList.vue`、`ToolboxImageWorkbench.vue` 和 `ImageManage.vue` 均为高复杂度页面。全站改造必须分阶段推进。

## 3. 目标与非目标

### 3.1 第一目标

操作效率与信息密度是第一优先级：

- 减少不承载信息或操作的占位。
- 提高 1440px PC 首屏可见的表格行、任务行和图片卡数量。
- 缩短搜索、筛选、恢复常用视图、查看详情和执行批量操作的路径。
- 强化状态层级，但不把所有正常状态包装成告警。
- 保持高频操作可发现、可键盘访问且不依赖纯 hover。

### 3.2 次要目标

- 继续提升全站视觉一致性。
- 让概览、监控、集合表格、媒体网格和复杂表单各自使用适合任务的密度。
- 降低页面局部 CSS 重复和后续样式漂移。
- 为分阶段回滚提供清晰边界。

### 3.3 非目标

- 不修改现有路由、菜单项名称、目标页面、鉴权或角色模型；只允许本规格明确的“服务与工具”分组合并、分组折叠和最近访问。
- 不修改 API 路径、请求参数、响应结构或后端统计口径。
- 不新增数据库字段、migration 或服务端用户偏好。
- 不重构现有业务流程、查询状态、批量语义或 Drawer 脏数据保护。
- 不新增 UI 框架、图标库、字体依赖或测试框架。
- 不引入暗色优先、玻璃拟态、渐变背景、营销式卡片墙、装饰性大图或大面积品牌色。
- 不在首轮提供用户可切换的紧凑/舒适模式。
- 不在首轮引入常驻分屏详情、拖拽列、拖拽仪表盘小组件或跨页面共享视图。

## 5. 候选方向与最终选择

并行评估过三套方案：

| 方向 | 优势 | 风险 | 结论 |
|---|---|---|---|
| Precision Ops | 集合管理效率高、与现有架构兼容、易推广到全站 | 视觉表达最克制，媒体沉浸感较弱 | 作为全站主方向 |
| Exception Command Center | 异常、积压和运行状态最突出 | 全站套用会让普通媒体管理和设置页过重 | 只增强 Dashboard 与 TaskMonitor |
| Media Workspace | 媒体浏览、选中、预览和核对上下文最好 | 不适合用户、设置和普通主数据页 | 只增强 VideoList 与 ImageManage 的 Drawer |

最终方案为：

- 以 Precision Ops 作为壳层、设计 token、集合工具条、表格和批量操作的全站基础。
- 吸收 Exception Command Center 的状态层级，但只使用接口真实提供的数据。
- 吸收 Media Workspace 的媒体检查器思路，但继续复用现有 560px 右侧 Drawer，不引入常驻分屏。

## 6. 设计原则

### 6.1 数据诚实

- 状态和指标必须标明统计口径。
- 全局总量与当前页派生数量不能混用。
- 没有全局失败率、告警或健康度数据时，不由前端推测制造。
- 颜色只强化已有业务状态，不创造新的状态含义。

### 6.2 按任务分级密度

- 列表、监控和批量处理页使用紧凑密度。
- 表单、编辑器和媒体预览使用中等密度。
- 窄屏保持舒适点击尺寸。
- 页面只声明自己的任务类型，尺寸由共享 token 和组件决定，不能各自发明密度。

### 6.3 集合优先

- 搜索、保存视图、筛选 chip、更多筛选、列设置和视图切换属于同一集合操作区。
- 集合页优先让用户扫描、比较、选择和批量处理资源。
- 卡片只用于真实资产条目、重复项、弹窗或工具，不把每个页面区块包装成浮动卡片。

### 6.4 操作可发现

- 高频详情入口始终可见。
- 低频动作可以收入更多菜单，但菜单按钮必须始终可见并有工具提示。
- 图片卡操作不能只在 hover 时出现。
- 状态必须同时使用文字、图标或形状和颜色。

### 6.5 最小业务扰动

- 保留现有 API、查询对象、事件处理、批量语义、路由和权限。
- 高复杂度 SFC 首轮只调整模板组织、共享组件接入和样式，不顺手重构业务脚本。
- 新增本地偏好必须版本化并在解析失败时回退。

## 7. 壳层与导航

### 7.1 桌面尺寸

| 项目 | 目标值 |
|---|---:|
| 展开侧栏 | 224px |
| 折叠侧栏 | 56px |
| 合并工作区页头 | 52px |
| 桌面主内容边距 | 20px |
| 1024px 以下主内容边距 | 16px |
| 手机主内容边距 | 12px |

现有 240/60px 侧栏收紧为 224/56px。手动折叠、本地持久化、1280px 以下自动折叠和 1024px 以下 Drawer 模式继续保留。

### 7.2 合并页头

普通业务页不再同时保留壳层顶栏和页面内 `PageHeader`。52px 工作区页头统一承载：

- 左侧：所属导航分组与当前页名。
- 中部：命令面板入口及 `Cmd/Ctrl+K` 提示。
- 右侧：页面级主操作和必要的视图操作。

页面级动作通过 Layout 的明确接口接入，不能由页面绝对定位到壳层。登录页和无 shell 工具页继续遵循各自现有边界。

现有 `PageHeader` 副标题不机械搬进 52px 工作区页头：

- 重复说明直接删除。
- 自动刷新、当前选择等运行状态移入集合工具条或状态区。
- 影响操作判断的范围说明移入对应内容区的单行提示。
- 无 shell 工具页可继续使用原有页面标题组件。

分阶段迁移使用现有 `hideShellPageHeader` 作为兼容边界：

- 未迁移页面保留自身 `PageHeader` 与 `meta.hideShellPageHeader = true`，继续按当前方式显示。
- 已迁移页面删除自身 `PageHeader`，移除该 route meta，并通过 Layout 的命名 slot 或等价明确接口提供页头主操作。
- Layout 继续从权威导航 helper 解析所属分组与页名。
- 全站迁移完成后，普通业务页不再使用 `hideShellPageHeader`；无 shell 工具页不渲染 Layout，不需要该标记。

### 7.3 导航收纳

- 主导航固定为 `仪表盘`、`媒体库`、`录入处理`、`服务与工具`、`系统` 五组。
- 原“服务”和“工具箱”只合并分组容器，不改变菜单项名称、路由、权限或工具页入口边界。
- 命令面板 helper 继续作为侧栏、移动 Drawer 和命令面板的权威菜单源。
- 导航顶部增加最多 3 项最近访问。
- 默认展开当前路由所在分组。
- 其它长分组允许收起，用户可手动展开。
- 最近访问和分组展开状态只保存到浏览器本地。
- 不新增收藏、服务端同步或第二份导航配置。

### 7.4 页面宽度

- 表格、监控和资产网格使用主区完整可用宽度。
- 不为装饰性居中效果给集合页增加窄 `max-width`。
- 表单和说明性内容可按阅读需要限制内部字段宽度，但页面区块本身不漂浮。

## 8. 视觉 token

### 8.1 色彩

| 角色 | 值 | 用途 |
|---|---|---|
| 画布 | `#F7F8FA` | 页面背景 |
| 表面 | `#FFFFFF` | 表格、工具区、Drawer 和输入表面 |
| 弱表面 | `#F1F3F5` | 表头、侧栏、只读或次级区域 |
| 主文字 | `#172033` | 标题、正文和关键数字 |
| 次文字 | `#475569` | 标签、说明和表格次级字段 |
| 弱文字 | `#64748B` | 元信息和辅助提示 |
| 柔和边框 | `#E2E8F0` | 区块、表格和控件边界 |
| 强边框 | `#CBD5E1` | 聚焦前边界和强调分隔 |
| 主操作 | `#2563EB` | 主按钮、选中态和链接 |
| 主操作悬停 | `#1D4ED8` | 主操作 hover/active |
| 成功 | `#047857` | 成功或可用状态 |
| 警告 | `#B45309` | 处理中、积压或需要注意 |
| 危险 | `#C81E1E` | 失败、删除和不可逆风险 |
| 信息 | `#0369A1` | 中性待处理或待确认状态 |

不得用大面积语义色填充页面。状态色主要用于状态点、图标、文字和小范围边界，并且不能成为唯一信息载体。

### 8.2 字体与字号

- 字体栈继续使用 `Inter`、`PingFang SC`、`Microsoft YaHei`、系统字体。
- 不增加新的外部字体依赖。
- 字距统一为 0。
- 表格和指标启用等宽数字。

| 层级 | 字号/行高 | 字重 |
|---|---:|---:|
| 页面标题 | 20/28px | 600 |
| 区块标题 | 14/20px | 600 |
| 正文 | 14/20px | 400/500 |
| 表格正文 | 13/18px | 400/500 |
| 辅助文字 | 12/16px | 400/500 |
| KPI 数字 | 24/30px | 600 |

### 8.3 间距、圆角和阴影

- 间距刻度：4、8、12、16、20、24、32px。
- 普通页面区块圆角不超过 8px。
- 基础圆角为 4/6/8px。
- 普通面板和 SectionCard 不使用常驻阴影。
- Drawer、Dialog、Popover、命令面板和批量浮条可以使用浮层阴影。
- hover 通过颜色、边框或轻阴影反馈，不使用会改变布局的缩放。

## 9. 密度规格

| 页面类型 | 控件高度 | 内容尺寸 | 区块内边距 |
|---|---:|---:|---:|
| 集合列表/批量页 | 32px | 表头 36px；文字行 40px；媒体行 52px | 12px |
| 监控页 | 32px | 任务行 44px；进度条 6px | 12px |
| 表单/编辑器 | 36px | 字段间距 16px | 16px |
| 媒体网格 | 32px 工具条 | 卡片最小约 184px；网格间距 12px | 卡片正文 8-12px |
| 1024px 以下 | 点击目标至少 44px | 表格容器内部滚动 | 12-16px |

任务行允许标题和 ID 两行显示，但必须保持固定高度。错误信息使用单行省略和完整内容提示，不用长错误文本撑高单行。

## 10. 共享设计架构

### 10.1 三层职责

1. L1 `theme.css`
   - 定义颜色、字体、字号、间距、圆角、阴影、断点、壳层尺寸和任务密度 token。
2. L2 `element-overrides.css`
   - 低特异性映射按钮、输入、选择器、表格、标签、分页、Drawer、Dialog 和 Popover。
3. L3 `components/base/`
   - 承载具有结构和行为的共享模式。

尺寸覆写不能无条件影响全站。紧凑尺寸必须由页面任务类型或明确 wrapper 进入，避免表单、上传和编辑器被集合页尺寸误伤。

### 10.2 共享组件边界

| 概念组件 | 职责 |
|---|---|
| `WorkspaceHeader` | 合并所属分组、页名、命令面板入口和页面主操作；可由 Layout 内部实现 |
| `MetricStrip` | 展示口径明确的紧凑指标；全局与本页数据并列时必须直接标注，不承载复杂图表 |
| `SavedViewTabs` | 切换、保存、重命名和删除页面内本地视图 |
| `CollectionToolbar` | 组织搜索、筛选 chip、更多筛选、列设置和视图模式 |
| `StatusIndicator` | 统一文字、图标/状态点和语义色 |
| `ResourceFrame` | 统一集合标题、内容、分页、首次加载、空态、零结果和错误态 |
| `AssetTile` | 图片预览、选择、标题、元信息、状态和更多菜单 |
| `BulkActionBar` | 延续当前会话内选择和批量操作语义 |
| `Inspector Drawer` | 复用现有 Drawer，统一媒体预览、分组信息和固定操作区 |

不是每个概念都必须创建新的 SFC。实施计划应先检查现有组件能否通过 props、slot 或样式扩展满足需求，只有真实消除重复时才新增组件。

## 11. 本地偏好与保存视图

### 11.1 保存范围

保存视图只保存页面已经支持的稳定状态：

- 筛选值。
- 显示列。
- 图片网格/列表模式。
- 页面内其它已存在且不改变业务语义的显示偏好。

不保存：

- 当前页码。
- 当前会话选择集。
- Drawer 打开状态或未保存表单。
- 服务器未支持的排序。
- 跨页面查询。
- 权限或业务状态。

### 11.2 数据安全

- 每类本地偏好使用独立 key 和 schema 版本。
- 读取时做结构校验。
- JSON 损坏、字段缺失或版本不兼容时回退默认。
- 本地存储不可用时保持当前会话可用，不让页面白屏。
- 切换保存视图属于选择上下文切换，必须清空或同步当前批量选择。
- 选择视图后手动修改筛选、列显示或网格/列表模式时，界面进入临时“自定义”状态，不静默覆盖已保存快照。
- 用户显式保存或更新视图后才写入快照。
- ImageManage 保存视图若包含网格/列表模式，应用时同步现有 `admin-imagemanage-view` 偏好；手动切换模式只更新当前“自定义”状态，直到用户显式保存。

## 12. 样板页设计

### 12.1 Dashboard

现有接口只提供：

- 短视频、电影、电视剧集和 AV 数量。
- 总用户数。
- 今日上传数。
- 转码队列长度。
- 磁盘总量与剩余量。
- 近 7 天上传趋势。

布局：

## 13. 加载、空态、错误和危险操作

### 13.1 首次加载

- 使用稳定尺寸骨架或局部 loading。
- 页头、筛选和最终内容区域不发生明显布局跳动。
- 空列表不能在请求未完成时短暂显示“暂无数据”。

### 13.2 后台刷新

- 保留已有数据。
- 在页头、刷新按钮或状态区域表达刷新进行中。
- 自动刷新不得重置滚动、筛选、分页或可见选择。
- 并发请求继续使用现有序列或取消策略防止旧响应覆盖新数据。

### 13.3 真正空态与筛选零结果

- 真正空态说明尚无资源，可提供创建或上传主操作。
- 筛选零结果说明当前条件无匹配，并提供清除筛选动作。
- 两者不能使用同一句“暂无数据”混淆。

### 13.4 读取失败

- 错误显示在对应内容区。
- 保留页头、筛选和用户当前上下文。
- 提供一个明确的重试动作。
- Toast 只作为补充，不能替代页面内错误状态。

### 13.5 危险操作

- 删除、停用或其它不可逆动作继续显式确认。
- 请求进行中禁用重复提交。
- 失败后保留当前选择和页面上下文。
- 成功后给出简短结果反馈并按既有规则刷新。

## 14. 响应式与可访问性

### 14.1 视口

必须验证：

- 375px
- 768px
- 1024px
- 1440px

规则：

- 1024px 以下使用现有 Drawer 导航。
- 窄屏点击目标不小于 44px。
- 页面不得出现整体横向滚动。
- 宽表格可以在自身容器内横向滚动。
- 卡片、按钮和长中文文字不得互相遮挡或撑破容器。

### 14.2 键盘与焦点

- 导航、命令面板、保存视图、筛选、列设置、卡片选择、行操作、分页和 Drawer 全部可键盘访问。
- 焦点样式始终可见。
- 更多菜单和纯图标按钮具有中文 `aria-label` 与 tooltip。
- 图片卡的更多操作不能只在 hover 时可见。

### 14.3 对比与动效

- 正文和交互文字对比度至少 4.5:1。
- 状态不只依赖颜色。
- hover 不造成布局位移。
- 动效控制在 120-240ms，并继续遵守 `prefers-reduced-motion`。

## 18. 风险与控制

### 18.1 全局 token 波及复杂页面

控制：

- 先更新语义 token，再通过页面任务类型进入尺寸覆写。
- 四个样板页通过后再推广。
- 不用无条件全局选择器把 32px 控件扩散到所有表单。

### 18.2 大型 SFC 回归

控制：

- 首轮不顺手重构业务脚本。
- 模板与样式调整保持小步提交。
- 每个样板页单独验证交互与测试。

### 18.3 本地偏好损坏或过期

控制：

- schema 版本。
- 结构校验。
- 解析失败回退。
- 本地存储异常不阻断页面。

### 18.4 收纳行操作导致不可发现

控制：

- 详情入口始终可见。
- 更多菜单始终可见且可聚焦。
- 危险动作使用明确文字、图标和确认。

### 18.5 指标视觉强化造成错误语义

控制：

- 只使用接口真实提供的数据。
- 明确全局与本页口径。
- 没有阈值时不将队列数量自动标记为异常。

## 19. 回滚

- 每个推广阶段使用独立提交。
- 基础 token、壳层、基础组件和每组页面改造保持可分别回退。
- 本次不涉及数据库、migration、API 或新依赖，代码回滚不需要数据修复。
- 本地偏好带版本，旧版本代码无法识别时回退默认，不影响业务数据。
- 阶段验收失败时先回退当前阶段，不反向修改已验收的业务契约。
