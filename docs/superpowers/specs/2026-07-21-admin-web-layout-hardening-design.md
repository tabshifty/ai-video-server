# 管理端布局健壮性修复设计规格

## 1. 文档状态

- 状态：已确认
- 确认日期：2026-07-21
- 适用范围：`admin-web/`
- 目标：修复真实管理端中可复现的内容挤压、溢出、触控可达性和焦点反馈缺陷；保留 Precision Ops 的信息密度、信息架构、路由、接口和业务流程。

## 2. 证据与边界

本规格基于管理员真实数据、375 / 768 / 1024 / 1440px 几何扫描、截图复核以及两轮独立源码审查。已确认的高密度布局、页面外层无横向滚动和由 `.table-wrap` 承担的宽表横向滚动不属于缺陷，不能改造成卡片列表或增加无意义留白。

本期不处理：

- 路由、权限、接口、请求 payload、数据模型、危险操作语义和刷新/轮询逻辑。
- 页面重新分组、表格改卡片、全站统一放大间距或新增明暗主题。
- 由当前无数据而无法安全触发的发布、删除、上传等直接写操作。

## 3. 设计选择

采用“共享容器优先、页面局部收敛”的最小方案：先修复所有消费者共享的批量操作条、命令面板、Drawer 窄屏密度和 Drawer 宽表容器；再修复已量化的页面局部最小宽度和动态文本边界。不得使用 `overflow-x: hidden` 掩盖问题，也不得让正常表格失去自身横向滚动能力。

### 3.1 共享交互容器

**批量操作条**

- `BulkActionBar` 在 1024px 以下改为纵向排列；操作组占满可用宽度并允许换行。
- 操作按钮保持既有 label、icon、禁用、loading 和 handler；全局窄屏 44px 目标高度继续生效。
- 这样 VideoList 和 ImageManage 的三项批量命令与“已选择 N 项”不再互相挤压或越出 375px 内容区。

**命令面板**

- 搜索面使用 `:focus-within` 显示与其它复合控件一致的焦点环；原生输入不再因为 `outline: 0` 丢失可见焦点。
- 结果列表增加 `overscroll-behavior: contain`，避免列表到滚动边界后继续带动遮罩后的页面。
- 快捷键、焦点陷阱、Esc 关闭、结果选择和焦点回归语义保持不变。

**Drawer 窄屏密度与宽表**

- 业务表单 Drawer 的可见内容根必须显式声明 `data-density="form"`，使 1024px 以下的输入、选择器、按钮、分页和 footer 操作消费既有 44px 规则；桌面仍为 form 的 36px 密度。
- VideoList 字幕表和 ImageManage 上传结果表各自包入局部 `.drawer-table-wrap`。该容器只负责 `width: 100%`、`min-width: 0` 和 `overflow-x: auto`，让表格在 560px/全宽 Drawer 中独立横滚，不牵连 Drawer body、表单或 footer。
- 不能为此修改全局 Drawer body 的横向 overflow，也不能改变表格列、字幕和上传结果数据。

### 3.2 集合和监控页

**任务监控桌面表格**

- 保留任务、状态、进度、剩余时间、已耗时、重试、错误、开始时间和进度更新时间九列及其现有格式。
- 只将各列 `min-width` / `width` 收敛到 1440px 主内容区可同时显示的总宽度：任务 210px、状态 96px、进度 150px、剩余时间 88px、已耗时 88px、重试 60px、错误 160px、开始时间 145px、进度更新时间 145px。
- 动态标题、ID 和错误仍使用既有省略及 Tooltip 语义；375 / 768px 仍在 `.table-wrap` 内横滚，不允许页面横滚。

**演员别名**

- 先以现有数组连接规则生成完整别名字符串；显示节点改为单行省略和可键盘聚焦的 Tooltip，`aria-label` 使用完整字符串。
- 空别名继续显示“暂无”。不得截断或改变原始别名数据。

### 3.3 视频和待删除工作台

**待删除短视频**

- 介于 1024px Drawer 模式与 1200px 宽桌面之间，保留队列与播放器双栏，但 `.pending-delete-detail` 改为纵向布局，避免标题区与四个动作按钮在不足宽度内互相挤压。
- 1200px 及以上恢复现有横向详情布局；1023px 及以下继续采用现有整页单列工作台。
- 队列顺序、选择、播放器、保留、最终删除、分页和空态语义均不变。

**视频详情 Drawer**

- “改为剧集分集”的季/集控件在 1024px 以下使用 `repeat(2, minmax(0, 1fr))` 网格；两个 `el-input-number` 使用 `width: 100%`，季/集文字保持与各字段相邻但不形成不可收缩的单行。
- 待绑定电视剧和 AV 候选行允许换行，所有动态标题、来源和外部标识均可在自身文本区域断词；不改变候选、刮削或跳转 handler。

### 3.4 图片合集 Drawer

- 排序数值输入保留桌面最大 200px，但必须以 `min(200px, 100%)` 收纳至编辑 Drawer 可用字段宽度。
- 关联图片 Drawer 的封面元信息容器使用 `min-width: 0`；合集名称、简介和统计说明支持 `overflow-wrap: anywhere`，防止无空格 URL、资源 ID 或异常长名称越出封面面板。
- Drawer 尺寸、关闭守卫、封面选择、图片加载和分页语义均不变。

## 4. 回归与验证

### 4.1 自动验证

- 为每个新增共享样式契约补充/扩展现有 Vitest 源码审计：批量操作条窄屏换行、命令面板焦点与滚动链、Drawer 表单密度、Drawer 宽表容器、季/集字段收纳、演员别名收敛、图片合集文本断词、待删除中等宽度详情布局和任务列宽总量。
- 每个测试先在实现缺失时红灯，再做最小 CSS/模板接线，随后运行定向测试。
- 收尾运行 `cd admin-web && npm test` 与 `cd admin-web && npm run build`。

### 4.2 浏览器验收

- 375 / 768 / 1024 / 1440px 检查所有路由的页面级 `scrollWidth === clientWidth`；仅 `.table-wrap` 和 `.drawer-table-wrap` 可横向滚动。
- 375px 选中视频/图片后检查三项批量命令；打开命令面板检查输入焦点环、超过列表高度的滚动链；打开视频详情检查季/集字段、候选长标题和字幕表；打开图片上传 Drawer 检查结果宽表。
- 375px 检查图片合集编辑 Drawer 的排序输入、关联图片 Drawer 的长名称/URL；1024px 检查待删除工作台的详情标题和动作；1440px 检查任务监控九列同时可见。
- 检查命令面板、Drawer、分页、批量操作条和动态 Tooltip 的键盘路径与焦点可见性；危险确认仅取消，不执行写操作。
