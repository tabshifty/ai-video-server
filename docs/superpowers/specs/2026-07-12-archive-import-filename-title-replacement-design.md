# 压缩包视频按文件名替换标题 - 设计规格

- 日期：2026-07-12
- 范围：管理端压缩包导入页的单文件与批量视频标题编辑
- 相关术语：`压缩包文件名派生标题`、`压缩包标题替换显式动作`、`压缩包旧标题转存描述`、`压缩包批量标题替换原子性`

## 1. 背景

压缩包导入的视频默认继承批次或分组标题，管理员可以单独编辑标题，也可以把多个视频统一覆盖成同一个标题。当前页面没有“按每个视频自己的文件名生成标题”的显式动作；现有批量编辑还会由前端逐个调用单文件接口，允许部分成功，无法保证标题与描述成对迁移。

本次增加一个明确、可预览的文件名标题替换模式。它只修改压缩包导入工作区中尚未入库的视频记录，不把命名规则隐式塞进“处理当前文件”或“处理所选”。

## 2. 目标与非目标

### 2.1 目标

- 单文件编辑支持从该视频的原始文件名生成标题草稿。
- 批量编辑支持按每个所选视频各自的文件名生成不同标题。
- 替换时把非空且不同于新标题的原标题转存到描述第一行，并保留原描述。
- 批量替换与同次勾选的标签、视频类型和合集字段整体成功或整体回滚。
- 保存时由服务端重新派生标题、复核状态和更新时间，前端预览不作为权威写入值。
- 关闭、取消、校验失败或事务失败均不产生部分修改。

### 2.2 非目标

- 不让“处理当前文件”“处理所选”自动改标题。
- 不处理图片、目录、不支持项以及 `processing`、`ready`、`existing` 等非 `pending` / `failed` 状态。
- 不清理缺少 `www.`、缺少 `@`、包含额外空格等近似广告文本。
- 不猜测性删除连字符、下划线、方括号或其它文件名符号。
- 不改变未选择“按各自文件名替换”时的既有批量编辑提交方式。
- 不反向修改已经入库的视频实体。
- 不新增数据库字段或迁移。

## 3. 标题与描述规则

### 3.1 文件名派生标题

派生顺序固定如下：

1. 读取文件记录的 `relative_path`，只取最后一段文件名，目录层级不进入标题。
2. 移除最后一个扩展名。
3. 使用大小写不敏感的全局字面匹配移除所有完整 `www.98T.la@`，前端等价正则为 `/www\.98T\.la@/gi`。
4. 去除首尾空白，把连续空白折叠为一个普通空格。
5. 保留其它符号原样。

若结果为空，单文件保持原标题和原描述；批量选择中任一文件结果为空，整批阻断并列出问题文件。

### 3.2 原标题转存描述

“原标题”指动作触发时文件编辑区展示的当前有效标题，比较前去除首尾空白；原标题与新标题采用精确字符串比较，大小写差异仍视为不同：

- 原标题非空且不同于新标题：新描述为 `原标题 + 换行 + 原描述`；原描述为空时不追加换行。
- 原标题为空或等于新标题：描述保持不变。
- 标题与描述作为同一条文件更新提交，不能只成功一个字段。

示例：

| 相对路径 | 原标题 | 原描述 | 新标题 | 新描述 |
|---|---|---|---|---|
| `目录/www.98T.la@ABC-123.mp4` | `旧标题` | `原说明` | `ABC-123` | `旧标题\n原说明` |
| `WWW.98t.LA@  A  B.mkv` | `批次标题` | 空 | `A B` | `批次标题` |
| `www.98T.la@-ABC.mp4` | `-ABC` | `已有说明` | `-ABC` | `已有说明` |
| `www.98T.la@.mp4` | `旧标题` | `原说明` | 无效 | 保持原值 |

## 4. 管理端交互

### 4.1 单文件编辑

- 视频标题输入项旁增加带图标和明确文案的“使用文件名”动作。
- 动作只在当前文件为 `pending` 或 `failed` 视频时可用；其它状态和媒体类型不显示可执行入口。
- 点击后先在标题、描述输入项中展示草稿，不立即请求保存。
- 派生结果为空时显示错误，标题和描述草稿保持原值。
- 若生成结果与当前标题相同且描述无需变化，提示“标题已与文件名一致”，不制造无意义脏状态。
- 生成后只修改标签、视频类型或合集时，文件名替换模式继续有效。
- 生成后手工修改标题或描述时，退出文件名替换模式；之后按普通单文件编辑保存管理员最终输入。
- 文件名替换模式未被手调时，“保存文件”通过新的语义化事务接口提交单个目标；普通编辑继续使用现有单文件接口。

### 4.2 批量编辑

- 视频标题由单一启用复选框调整为三态模式：`不修改`、`统一标题`、`按各自文件名替换`。
- `不修改` 和 `统一标题` 沿用既有行为；只有 `按各自文件名替换` 使用新事务接口。
- 文件名模式下禁用“说明”统一覆盖，避免破坏每个视频各自的原标题与原描述；标签、视频类型、视频合集和视频关联图片合集仍可同时修改。
- 预览展示目标总数和前 5 条“原标题 -> 新标题”，超过 5 条时显示剩余数量。
- 只要选择集中存在跨批次、非视频、非 `pending` / `failed`、更新时间缺失或空派生标题，文件名模式不可保存，并显示问题文件。
- 关闭或取消弹窗不落库；保存失败时弹窗与输入继续保留。

## 5. 架构与职责

### 5.1 管理端

- `ToolboxArchiveImport.vue` 负责模式状态、草稿、互斥控制、预览和反馈。
- 新增独立纯函数模块承载前端标题派生与描述合并，避免继续扩大页面组件。
- `admin.js` 增加语义化批量更新请求；API 测试固定请求路径和负载结构。
- 前端派生结果只用于预览。文件名模式保存时不把最终标题和描述作为权威值发给服务端。

### 5.2 服务端

- 新增 `PUT /api/v1/admin/archive-import/files/batch-update`，接受一个或多个目标。
- Handler 只负责负载解析、UUID 与时间格式校验、服务错误到统一响应的映射。
- `ArchiveImportService` 负责目标锁定、业务校验、权威标题派生、描述迁移、字段覆盖语义与事务提交。
- Go 侧标题派生与描述合并保持纯函数，并与前端共享同一组固定样例测试。
- 不新增数据表或数据库迁移。

## 6. 接口契约

### 6.1 请求

```json
{
  "targets": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "updated_at": "2026-07-12T05:00:00Z"
    }
  ],
  "title_mode": "filename",
  "update_tags": true,
  "tags": ["标签一", "标签二"],
  "update_video_type": false,
  "video_type": "short",
  "update_video_collection_ids": false,
  "video_collection_ids": [],
  "update_image_collection_ids": false,
  "image_collection_ids": []
}
```

约束：

- `targets` 至少包含一个目标，ID 不得重复。
- 本次只支持 `title_mode = filename`；统一标题继续走既有路径，不为未来模式预留未使用分支。
- `updated_at` 必须来自当前批次详情响应，用于保证保存结果与管理员看到的预览对应。
- 文件名模式不接受统一说明字段，也不接受前端生成的最终标题或描述。
- 其它字段使用明确的 `update_*` 开关；未启用的字段保持每个文件现值。
- 视频关联的 `image_collection_ids` 继续遵守最多一个图片合集的既有约束。

### 6.2 成功响应

沿用 `{ code, msg, data }`：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "updated_count": 1,
    "items": []
  }
}
```

`items` 返回更新后的文件记录。前端成功后刷新批次详情并关闭相应编辑弹窗。

### 6.3 失败响应

失败继续使用统一响应包装，`data.reason` 为稳定机器码，`data.issues` 用于展示问题文件：

```json
{
  "code": 1078,
  "msg": "压缩包文件批量更新失败",
  "data": {
    "reason": "stale_target",
    "issues": [
      {
        "id": "11111111-1111-4111-8111-111111111111",
        "relative_path": "目录/视频.mp4",
        "message": "文件信息已变化，请刷新后重试"
      }
    ]
  }
}
```

稳定原因包括：

- `invalid_selection`：空选择、重复 ID、找不到目标或跨批次。
- `ineligible_target`：非视频或状态不是 `pending` / `failed`。
- `stale_target`：`updated_at` 与当前记录不一致。
- `empty_derived_title`：至少一个文件无法得到非空标题。
- `invalid_patch`：其它勾选字段不满足既有约束。
- `update_failed`：事务执行失败。

## 7. 服务端事务与竞态

批量服务按以下顺序执行：

1. 解析并去重检查目标；按 UUID 固定排序，降低并发锁顺序不一致的风险。
2. 开启事务，按固定顺序读取并锁定全部文件记录。
3. 校验实际返回数量、同批次、文件类型、状态和 `updated_at`。
4. 在事务内读取批次与相关分组默认值，先为全部目标计算标题、描述和其它字段的最终变更计划。
5. 任一目标校验失败时不执行写入，返回完整问题清单。
6. 更新文件字段和 `field_overrides`，所有记录使用同一事务提交。
7. 任一 SQL 失败时回滚全部目标；接口不返回部分成功结果。

`ProcessFile` 当前会先读取文件快照，再把状态改为 `processing`，之后继续使用旧快照。为封住 pending 到 processing 的并发窗口，标记成功后必须重新读取文件元数据：

- 处理先把状态改为 `processing`：标题替换在校验阶段被拒绝。
- 标题替换先持锁并提交：处理的状态更新随后完成，再读取到新标题和描述。

这里只增加一次短读取，不在视频复制、哈希或入库期间持有长事务锁。

## 8. 前端错误恢复

- 本地发现空派生标题：保持草稿，不发请求，列出相对路径。
- 服务端返回 `stale_target` 或 `ineligible_target`：回滚已经由服务端保证；前端刷新批次详情并重新计算预览，保留标签、类型和合集输入。
- 网络或通用服务错误：保留全部草稿和预览，允许重试。
- 若服务端已经提交但成功响应丢失，重试时旧 `updated_at` 会得到 `stale_target`；刷新后显示真实已提交结果，不重复迁移描述。
- 成功只提示“已更新 N 个视频”，不再显示部分成功统计。

## 10. 人工验收

1. `pending` 视频单文件替换后，标题来自文件名，原标题位于描述第一行；保存前可取消。
2. 大小写变体和同一文件名中的多个完整广告文本都被删除；近似文本与其它符号保留。
3. 原标题等于新标题时不重复写入描述。
4. 批量 6 个视频时预览前 5 条并显示剩余 1 条，保存后每个视频得到各自标题。
5. 文件名模式不能同时统一覆盖说明，但可同时修改标签、类型和合集。
6. 任一文件派生为空时整批不保存，所有标题和描述保持原值。
7. 预览后任一目标进入 `processing` 或被其它操作更新时，整批回滚并刷新预览。
8. `processing`、`ready`、`existing`、图片和其它条目没有可执行入口。
9. 模拟事务中途失败时没有部分更新；重试不会重复向描述插入原标题。
10. “处理当前文件”“处理所选”行为保持不变，不自动替换标题。

## 11. 回滚与文档

接口为新增能力且没有数据库迁移，代码回滚只需撤销管理端入口、路由、Handler 和服务方法；既有上传、编辑与处理接口继续可用。管理员已经确认保存的数据属于正常元数据修改，代码回滚不自动反向恢复，但原标题仍按本规格保留在描述中。

长期术语和边界已同步到根级 `CONTEXT.md`。该方案易于按功能入口撤回，也没有跨系统不可逆取舍，因此不新增 ADR。
