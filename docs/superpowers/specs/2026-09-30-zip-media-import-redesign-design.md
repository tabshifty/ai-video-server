# 压缩包视频图片导入重构设计

## 1. 背景与目标

现有管理端已经可以上传压缩包、递归解包、识别视频和图片，并在网页上编辑条目后入库。当前模型仍把视频关联图片合集保存为单个 `videos.image_collection_id`，压缩包页面中的图片合集字段同时承担“图片自身所属合集”和“视频关联图片合集”两种语义，无法表达一个视频对应多个图片合集，也无法表达视频合集与图片合集之间的继承关系。

本次重构的目标是：

- 支持 ZIP 内任意多层目录，按媒体所在目录自动生成导入组。
- 同一导入组内的每个视频默认关联该组内的全部图片。
- 管理员在网页上确认、调整视频与图片的关系，以及视频合集和图片合集的归属。
- 一个视频可以属于多个视频合集，一个图片可以属于多个图片合集。
- 一个视频合集可以关联多个图片合集；视频加入视频合集后继承这些图片合集，并允许视频级增删。
- 上传、解包、编辑和入库分阶段进行；确认入库后逐项处理，失败项可重试，成功项保留。
- 兼容已有视频的单图片合集数据和既有普通上传流程。

非目标：本次不改变压缩包格式支持范围、不引入压缩包描述文件、不改变视频转码和图片存储的基础格式、不把导入组永久暴露为业务合集。

## 2. 术语与边界

### 2.1 导入批次

一次上传的压缩包及其解包目录、文件清单、网页编辑状态和处理统计。批次在确认入库前是暂存工作区，删除批次不会删除已经入库的媒体。

### 2.2 导入组

由同一压缩包目录下可处理媒体组成的临时工作单元。目录层级保留在 `relative_path` 中；默认按媒体所在的最深目录分组，压缩包根目录下的媒体归入根目录组。导入组不改变文件存储路径，也不是视频合集或图片合集。

导入组用于批量设置元数据、确定默认的媒体关系和执行组级入库。父目录中的图片不会自动关联到子目录视频，除非管理员在网页上手动调整。

### 2.3 视频与图片关系

导入阶段按组生成候选关系：组内每个视频关联组内全部图片。该关系在网页上可按视频增删图片。入库后关系以稳定的媒体关系数据保存，重复入库不会重复产生关系。

### 2.4 合集

- 视频合集：视频与视频合集是多对多关系。
- 图片合集：图片与图片合集是多对多关系。
- 视频合集与图片合集：两类合集之间是多对多关系。
- 视频级图片合集：视频可以直接关联多个图片合集，作为视频合集继承结果之外的补充或移除后的最终覆盖。

“图片合集”在视频级关系和图片自身归属中是同一个业务实体，但网页必须使用明确的字段名称区分“视频展示的图片合集”和“图片入库后的图片合集”。

## 3. 方案比较与选择

### 方案一：扩展现有导入工作台（采用）

保留当前批次、文件清单、导入组和逐项处理接口，在其上增加目录分组、媒体关系暂存、合集多对多关系和确认入库步骤。优点是复用现有 ZIP 解包、编码处理、去重、重试和管理端入口；已有批次可以继续打开。代价是需要拆开当前文件条目中的图片合集语义，并补充迁移和兼容读写。

### 方案二：新建独立导入系统

用新的批次、媒体暂存和入库接口替换旧工作台。模型边界更干净，但会重复实现解包、密码、编码、去重和失败恢复，旧批次也需要单独迁移，风险和维护成本较高。

### 方案三：要求压缩包附带描述文件

由 ZIP 内的 JSON 或 YAML 声明分组、媒体关系和合集。机器导入精确，但增加制作成本，无法满足“上传后通过网页操作”的主要流程，也不能替代网页审核。

采用方案一。

## 4. 端到端流程

### 4.1 上传与扫描

1. 管理员上传 ZIP，可填写批次标题、默认描述、默认标签和默认合集。
2. 服务端保存原始压缩包，递归解包并记录每个条目的相对路径、目录、媒体类型、大小、MIME、状态和错误原因。
3. 对视频和图片条目按所在目录创建或更新导入组。
4. 对每个组生成视频与图片的候选关系；没有图片的视频保持空关系，没有视频的图片仍可独立入库。
5. 批次进入“待确认”状态。解包、密码或编码失败时保持对应错误状态，允许补充密码或编码后重新扫描。

### 4.2 网页确认

工作台分为四个区域：

- 批次概览：显示目录数、视频数、图片数、重复数、错误数和待确认数。
- 导入组列表：按目录展示每组的视频、图片、合集和处理状态，可批量编辑。
- 视频关系编辑：以视频为主项展示当前关联图片，支持从同组图片中增删；支持预览图片。
- 合集设置：批次默认值、组级覆盖和单文件覆盖。视频合集字段使用多选；视频关联的图片合集使用多选；图片入库合集单独显示。

覆盖优先级为“单文件 > 导入组 > 批次默认”。只要某一级明确覆盖，下面级别的更新不会覆盖它。新建合集后立即回填当前选择器，不需要复制 ID。

页面必须区分以下操作：

- “保存设置”：只保存暂存工作区，不创建视频或图片实体。
- “确认入库”：锁定当前批次配置并开始逐项入库。
- “重试失败项”：只处理失败项，不重复处理成功项。
- “删除批次”：删除未入库的批次文件和暂存记录；已入库媒体不受影响。

确认前必须通过校验：每个视频的关系只引用同批次图片；每个合集 ID 存在且类型正确；条目路径和暂存文件仍存在；已开始处理的条目不能被编辑。

### 4.3 逐项入库

确认后批次进入“处理中”，服务端按媒体条目逐项执行：

1. 先写入或复用视频、图片实体，使用现有哈希和去重逻辑。
2. 在同一媒体事务中写入视频合集、图片合集以及视频和图片的直接关系。
3. 视频按类型进入现有转码或刮削队列；图片完成文件保存后标记可用。
4. 更新导入条目的 `linked_video_id` 或 `linked_image_id`、状态、错误原因和处理时间。
5. 继续处理其他条目，不因单项失败终止整个批次。

成功项状态为“已入库”或“已存在”；失败项状态为“失败”，保留可读错误和重试入口。批次状态根据统计显示“已完成”“部分失败”或“处理中”。

## 5. 数据模型

### 5.1 业务关系表

新增或调整以下关系：

- `video_image_collections(video_id, image_collection_id)`：视频与图片合集多对多关系，唯一键为两列组合。
- `video_collection_image_collections(video_collection_id, image_collection_id)`：视频合集与图片合集多对多关系，唯一键为两列组合。
- `video_images(video_id, image_id, source)`：视频与图片多对多关系，`source` 区分导入组候选、视频合集继承和人工直接关联；删除视频或图片时级联删除。

现有 `videos.image_collection_id` 迁移为 `video_image_collections` 中的一条关系。迁移完成后保留旧列一段兼容期：读取接口优先读取新关系，旧写入接口同步维护默认的第一条关系，待所有调用方迁移后再删除旧列。

### 5.2 导入暂存表

现有 `archive_import_batches`、`archive_import_files`、`archive_import_groups` 继续使用并扩展：

- `archive_import_groups.directory_path`：组对应的规范化目录路径。
- `archive_import_files.group_id`：文件所属导入组。
- `archive_import_file_images(file_id, image_file_id, relation_source)`：待入库的视频条目与图片条目的暂存关系。
- 将文件条目中的 `image_collection_ids` 改名或拆分为 `video_image_collection_ids` 与 `image_collection_ids`，前者只表示视频展示的图片合集，后者只表示图片自身入库合集。
- 批次增加 `confirmed_at`、`confirmed_by` 和必要的确认版本号，用于防止确认后旧页面覆盖配置。

导入暂存关系只引用同一批次的文件 ID；入库成功后通过 `linked_*_id` 映射到正式媒体关系。

### 5.3 合集继承解析

入库前计算每个视频的最终图片合集集合：

```text
视频合集继承的图片合集
  + 视频直接指定的图片合集
  - 网页明确移除的继承关系
```

最终集合去重后写入 `video_image_collections`。如果视频不属于任何视频合集，也可以只使用视频级图片合集。删除视频合集与图片合集之间的关系不会删除媒体，只影响后续继承解析；已经落库的直接视频关系是否同步移除由单独的管理操作决定。

## 6. 接口与状态

接口继续沿用管理员压缩包导入路由风格，新增以下能力：

- 获取批次详情时返回导入组、候选图片关系、最终解析后的合集预览和确认版本。
- 保存组级和单文件级媒体关系，要求携带条目更新时间或确认版本，过期时返回冲突。
- 保存视频合集与图片合集关联。
- 确认批次入库，返回批次处理任务标识和初始统计。
- 查询逐项处理结果和失败原因。
- 重试指定失败项或整批失败项。

状态至少包含：`uploaded`、`ready`、`processing`、`partial`、`completed`、`failed`、`needs_password`、`needs_encoding`。确认前的 `ready` 表示可编辑，确认后的 `processing` 表示已锁定编辑。

所有保存接口必须校验条目属于当前批次、媒体类型匹配、合集类型正确、关系没有跨批次引用。确认接口必须幂等；重复确认不得重复创建视频、图片或关系。

## 7. 错误处理与兼容策略

- 压缩包解包失败：批次进入对应错误状态，保留原包，补充密码或编码后清理旧清单并重新扫描。
- 媒体文件不存在或损坏：条目标记失败，其余条目继续；修复文件后可以重试。
- 合集被删除或停用：确认前阻止入库并列出受影响条目；已入库数据保留，后续由合集管理规则处理。
- 重复媒体：沿用现有哈希去重，条目标记“已存在”，仍补齐缺少的合集和关系。
- 转码或刮削入队失败：条目标记失败并保留已创建媒体 ID；重试时必须复用该媒体 ID 或按现有重转码规则恢复，不能产生孤儿视频。
- 旧视频只有 `image_collection_id` 时，迁移脚本写入一条新多对多关系；旧值为空不生成关系。
- 旧批次缺少导入组时，打开详情时按相对路径即时生成组并写回，保证历史批次可继续处理。

## 8. 测试与验收

### 服务端

- 多层目录、根目录媒体和同名不同目录媒体的分组测试。
- 一个组内多个视频、多张图片时，候选关系为全连接；增删关系后只影响指定视频。
- 视频多视频合集、图片多图片合集、视频合集多图片合集的去重和继承解析测试。
- 旧单图片合集字段迁移和兼容读取测试。
- 确认入库幂等、重复文件、单项失败继续处理、失败重试和过期版本冲突测试。
- 转码入队失败不会产生无关联孤儿记录，重试后能恢复的测试。

### 管理端

- 上传后按目录展示导入组和媒体数量。
- 组级设置继承到文件，单文件覆盖不被批量保存覆盖。
- 视频图片关系编辑只能选择同组图片，图片预览和删除关系即时反映。
- 视频合集和图片合集多选、合集关联创建、删除和回填测试。
- 确认后编辑入口锁定，成功项和失败项状态展示正确，失败项重试只处理失败项。

### 验收场景

使用包含三层目录、一个目录多个视频和图片、根目录媒体、重复文件和损坏文件的 ZIP：上传后组数和数量正确；第一组每个视频默认关联组内全部图片；将一个视频加入两个视频合集并关联两个图片合集；确认入库后成功项正常可查，损坏文件单独失败且可重试，重复确认不新增媒体。

## 9. 回滚与发布顺序

1. 先发布关系表和兼容读取代码，执行旧字段到新关系的可重复迁移。
2. 再发布服务端导入接口和管理端工作台，默认保留旧接口兼容写入。
3. 验证历史视频、历史批次和普通上传后，切换管理端到新字段。
4. 稳定运行后再删除旧字段和兼容代码；删除前保留数据库备份和反向迁移脚本。

关系表和导入暂存扩展均可单独回滚。任何已入库媒体不会因为代码回滚而被删除；关系数据通过反向迁移恢复旧的第一条图片合集关系。
