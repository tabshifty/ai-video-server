# 压缩包导入选择框搜索候选收敛设计

## 状态

已确认。确认日期：2026-07-18。

## 背景与根因

管理端压缩包导入页在上传默认值、单文件编辑、批量编辑和分组默认值中复用了标签、视频合集、图片合集三组远程选择器。共享加载器收到新搜索结果后，会把 `getOptions()` 返回的旧候选与新结果合并；压缩包页当前把完整的历史候选数组作为 `getOptions()` 返回值，因此搜索关键词变化后，旧关键词的无关候选仍会出现在下拉列表中。

## 目标与非目标

目标：

- 搜索后下拉列表以当前关键词的接口结果为准，不继续显示历史未选候选。
- 已选标签、视频合集和图片合集仍保留对应选项，避免候选刷新后已选值显示为原始 ID 或无法正常移除。
- 标签、视频合集、图片合集的所有压缩包导入选择位置使用同一规则。

非目标：

- 不修改后端搜索接口、查询参数、分页大小或返回结构。
- 不改变远程搜索的 180ms 防抖和旧请求结果丢弃规则。
- 不改变普通视频上传页的候选保留语义。
- 不改变选择值、上传 payload、保存 payload、合集创建回填和任何非远程类型选择框。

## 设计

远程加载器的调用方式保持不变。压缩包页只调整三个 loader 的旧选项来源：旧选项必须从当前工作台表单模型中的已选值推导，而不能直接返回完整 `tagOptions`、`collectionOptions` 或 `imageCollectionOptions` 数组。

由于多个弹窗共用同一组候选状态，已选值按候选类型取压缩包工作台各表单模型的并集：上传表单、单文件编辑表单、批量编辑表单和分组默认值表单。并集只用于保留已选值已有的显示选项，不把候选数组本身重新当作已选值，也不制造不在当前查询结果中的新候选。

每次远程请求完成后，加载器继续执行既有的 latest-wins 检查，然后由现有去重合并逻辑生成“当前查询结果 + 当前已选值”的列表。清空搜索关键词时，当前结果改为热门标签或默认合集候选；上一次非空关键词的未选结果不再进入列表。

## 验收条件

1. 先搜索关键词 A，再搜索关键词 B；B 的结果可以显示，A 中未选且不属于 B 的候选不再显示。
2. 搜索过程中已有标签或合集被选中；搜索结果刷新后，已选值仍显示原标签/名称，并可正常取消选择。
3. 清空关键词后只显示默认候选和当前已选值，不恢复更早搜索过的未选候选。
4. 连续搜索时旧请求晚于新请求返回，旧结果仍不能写回。
5. 压缩包上传、单文件保存、批量保存、分组保存的值和请求 payload 与修复前一致。

## 验证策略

先在现有管理端测试中补充一个能证明“历史未选候选不被保留、已选候选仍保留”的红灯契约，再实现最小改动。随后运行压缩包页与远程加载器定向测试、管理端完整测试、`npm run build`、`git diff --check` 和本次文件的中文乱码扫描。
