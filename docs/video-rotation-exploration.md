# 视频方向修正探索

状态：功能已实现并完成本地验证，尚未部署；手机、TV 真机及用户实际视频待验收。

## 当前结论

服务器具备旋转视频画面的技术基础，已提供管理端方向修正功能。采用优先无损策略：兼容时修改旋转元数据并直拷媒体流，需要旋转画面重新编码时在提交前明确提示并确认。已有滤镜实验仅证明重新编码路径可行，本机已验证元数据方式的流数据与显示方向、VideoToolbox 重编码及数据库处理链路；手机、TV 真机和实际问题视频尚未验证。

## 已核实事实

- 转码参数及滤镜入口位于 `pkg/ffmpeg/ffmpeg.go:59`、`:89`；当前没有旋转参数，已有缩放滤镜，后续需要组合滤镜顺序。
- 转码后会重新截图并探测宽高，见 `internal/services/transcode.go:150`；已有自定义封面是否保留需要另行定义。
- 当前重转码先把视频改为 `uploaded`，播放要求 `ready`，直接复用会暂时不可播放，见 `internal/handlers/admin.go:681`、`internal/handlers/video_source.go:111`。
- 原片可能被清理，重转码可退回现有播放文件，见 `internal/queue/tasks.go:309`、`internal/handlers/admin.go:1210`；重复旋转可能产生重复有损编码。
- 杜比视界原始播放源明确禁止重转码，见 `internal/handlers/admin.go:668`；不能默认普通旋转流程覆盖此类视频。
- 当前编码器使用 macOS VideoToolbox，见 `pkg/ffmpeg/ffmpeg.go:85`；部署支持范围不能泛化为任意服务器。
- 当前探测结构没有读取旋转标记；设计时须处理源文件旋转信息、FFmpeg 自动旋转与人工修正的组合。

## 已确认需求

- 操作入口：管理后台 → 视频详情 →“修正方向”，管理员逐条选择顺时针 90°、180°、逆时针 90°。
- 优先采用修改旋转元数据、不重新编码媒体流的无损方式；需要重新编码时必须在提交前说明原因、耗时与画质影响，由管理员确认，不静默转为重编码。
- 服务器永久修正视频文件，全端播放和下载修正文件均生效。
- 为节省硬盘空间，成功修正后不保留旧播放文件及该视频独占的服务端原片恢复副本；不提供依赖旧文件的恢复；纯元数据旋转可以再次反向调整标记，但不承诺恢复原文件字节或编码前画质。
- 空间策略见 [架构决定 0035](adr/0035-video-rotation-without-source-retention.md)。删除旧文件须在新文件校验及切换成功后执行，处理期间需要临时输出空间；失败时保留可用旧文件并清理半成品。不能把删除旧文件作为启动转码前腾空间的手段。
- 本地视频修正不等于删除 115 云端文件或共享导入来源；清理边界需要确保不影响其它资源。

- 旋转角度以操作时当前正确应用文件旋转标记后的显示画面为基准。
- 自动截图封面重新生成，自定义海报保留。
- 处理期间仍提供旧视频，成功后新打开的播放和下载使用修正文件，不主动中断已有播放会话。
- 首期排除杜比视界源，管理端禁用旋转并给出中文原因，后端也必须拒绝。

## 曾比较的方向

| 方向 | 效果 | 代价与限制 |
| --- | --- | --- |
| 服务器旋转画面并重新编码 | 各端使用修正后的文件，下载该文件也保留效果 | 处理耗时、临时空间与编码损失 |
| 修改文件旋转元数据 | 通常无需重新编码画面 | 各播放器是否遵从标记需要实测 |
| 保存角度并由客户端旋转 | 可快速改变播放显示 | 各端需适配，文件及外部播放器不自动改变 |

## 操作说明

管理后台 → 视频管理 → 编辑（视频详情）→ 文件与播放 → 修正方向。选择角度及处理方式，点击“检查处理方式”，确认提示和临时空间后提交。默认优先无损；若外部播放器不识别方向，可明确选择重新编码并重新预检。详情内显示进度、处理结果及清理待重试原因。

## 实施设计

以下为当前实现与恢复约定。

### 操作与范围

- 管理端视频详情增加“修正方向”，支持顺时针 90°、180°、逆时针 90°，按钮含义与当前画面一致。
- 提交前展示“无损旋转”或“需要重新编码”及判断原因，说明成功后删除旧文件、无旧文件备份；重编码方式另行明确画质影响和处理耗时，显示任务进度与失败原因。
- 只接受已就绪且本地播放文件位于视频独占目录的普通视频。杜比视界、HDR、非方形像素、镜像或非直角显示矩阵、多视频流、内嵌封面及暂不支持的字幕/数据流会拒绝处理，以避免损坏画质或丢失媒体流；页面展示服务端返回的原因。
- 视频 ID、标题、合集、标签、收藏、观看进度和外置字幕关系保持；旋转不改变时间轴，不自动旋转字幕文字。
- 不新增客户端旋转功能或下载管理系统；已有播放文件的下载读取修正后的内容。设备已经下载、缓存的旧文件不会远程改写。

### 方式判定与兼容性

- 无损旋转仅改变容器的旋转标记或显示矩阵，媒体流直拷；它不旋转编码像素、不改变编码尺寸，也不代表原地修改。重新封装通常仍需完整新输出空间。
- 当前无损候选范围为 MP4/MOV 容器的 H.264/HEVC 视频，配合 AAC/MP3/AC3/EAC3/ALAC 音频及可选 mov_text 内嵌字幕；实际容器及流信息由 ffprobe 探测。已以 H.264 样本验证数据流直拷和有效显示方向，所有具体播放器组合仍需现场验收，不能将技术可写入标记等同真机兼容。
- 下载文件保留方向标记，但任意第三方播放器是否支持无法普遍保证；不支持标记的播放器需选择重新编码方式。管理端同时允许明确选择重新编码以解决实际兼容问题。
- 提交前探测结果绑定当前文件版本和处理方式，文件变化后须重新判定。无损方式执行失败时保留旧文件并报告原因；若建议重编码，重新展示提示并取得确认，不由 worker 静默改方式。
- 首期杜比视界仍排除，两条处理路径都必须检查，不因元数据路径可能保留媒体流而绕过既有保护。

### 作业与并发

- 新增独立方向修正作业，复用现有队列、硬件编码和进度能力，不直接套用会把视频改为 uploaded/processing 的重转码入口；修正期间视频保持 ready。
- 固定本次作业输入为受理时的当前播放文件，而非旧原片，避免第二次修正回到原片基准。
- 作业持久化视频、操作者、相对角度、输入版本、唯一请求标识、处理方式、已确认的输入版本及兼容判定、输出路径、处理阶段与错误摘要。请求重放返回同一作业；同视频的不同修正并发请求返回冲突。
- 作业需与重转码、删除等会改写同一视频文件的操作互斥，锁不能仅依赖单进程内存。发布前校验输入版本及视频状态仍匹配，避免覆盖更新或复活已删除视频。
- 队列只负责唤醒，数据库中的作业阶段是恢复依据。切换后重试只继续清理，不再次把角度叠加到新文件。

### 文件处理与发布

1. 在输出所在文件系统预检可用空间，以预计输出大小加余量判断，不复制一份完整旧视频作为备份；处理时仍需容纳旧文件和新输出。
2. 探测当前播放文件的显示矩阵、编码尺寸、显示尺寸与兼容性，以当前显示方向叠加人工角度；明确 FFmpeg 旋转正负方向与界面顺逆时针约定，不能直接假设数值符号一致。
3. 输出到作业专属临时文件：无损路径直拷媒体流，仅合成并写入目标旋转标记，不施加像素滤镜；重编码路径先应用已有显示方向再旋转画面，移除已应用标记，必要时组合缩放滤镜。重编码优先维持当前编码类型、分辨率等级和既有音轨，兼容音频尽量直拷。
4. 验证输出非空、时长合理、有效显示方向与显示尺寸正确、音视频可读取；无损路径还要核对媒体流未重新编码，编码尺寸通常保持，显示尺寸在 90°/270° 时交换。基于最终显示方向生成自动截图，自定义海报保持。现有宽高字段写入有效显示尺寸，更新主播放文件大小与兼容元数据。
5. 完成文件写入并发布到唯一新路径，在数据库事务中条件切换播放指针、自动截图指针及相关元数据，同时登记待清理路径；数据库和文件系统不能假设支持同一原子事务。
6. 切换成功后清理被替代的旧播放文件及该视频独占的服务端原片，修正失效的原片引用，防止以后重转码回到未修正内容；保留共享导入资源、云端文件、自定义海报和外置字幕。
7. 旧文件清理完成才显示整体完成；清理失败展示“画面已修正，旧文件清理待重试”，后台仅重试清理，不重新转码或回退新播放文件。

新输出采用唯一版本路径，避免原地覆盖正在读取的视频。已有打开的文件读取可继续，但跨发布时刻的新 Range 请求可能读到新版本；需校准媒体响应验证信息并验证各端重新加载行为，不能承诺所有播放器无缝跨版本续播。无论如何不主动向客户端发送停止播放命令。

媒体源响应使用私有缓存重新验证及包含文件路径版本、大小和纳秒修改时间的 ETag，避免同秒修正错误返回 304；旋转生成的封面 URL 带作业版本参数。设备已经缓存或下载的旧文件不会远程改写；不保留旧文件作为无限期媒体版本兼容副本。

### 失败与恢复

| 场景 | 必须达到的结果 |
| --- | --- |
| 预检空间不足 | 拒绝启动并提示空间不足，旧文件仍可用 |
| 输出过程中磁盘写满、转码或校验失败 | 不切换播放指针，清理半成品并保留旧文件 |
| 文件已就绪但数据库切换失败 | 旧文件继续播放；根据持久化作业恢复发布或清理未引用的新输出 |
| 发布成功后进程崩溃 | 恢复到旧文件清理阶段，不再次旋转 |
| 旧文件删除失败 | 新视频继续可用，显示清理待重试，保留精确待清理路径 |
| 重复点击、重复投递、任务重试 | 同一请求最多发布一次；不得累积旋转角度 |
| 视频被删除或被其它操作更新 | 版本校验失败，停止发布并清理本作业输出 |

删除前必须确认文件位于允许的服务端存储范围、确属旧版本且未被任何当前播放引用；已经不存在视为清理成功。共享路径无法证明独占时保留并显式报告原因。已有打开文件描述符时，磁盘空间可能到读取结束后才实际释放。

## 验收清单

- 横向、竖向视频的三个角度均正确；90°/270° 后有效显示宽高交换，无损路径编码尺寸保持，重编码路径像素方向与尺寸正确。
- 无损路径验证媒体流未重新编码、画质不变及既有音轨保留；重编码提示必须在提交前确认。无损失败不能静默执行重编码。
- 带已有旋转标记的样本无二次旋转；连续两次顺时针 90° 等于相对最初显示画面旋转 180°。
- 管理端、手机、TV 和下载后外部播放均验证新文件方向；已缓存旧文件不作为服务端修正失败。
- 处理期间旧视频可打开，成功后新会话读取新文件；Range、缓存及重新加载行为验证通过。
- 自动截图更新、自定义海报保留，音画同步、视频时长和外置字幕时间轴正常。
- 成功后磁盘不保留旧视频及独占原片恢复副本；清理失败有明确状态且可恢复。
- 空间不足、重新封装失败、转码失败、数据库切换失败、切换前后崩溃和清理失败均进行故障验证。
- 并发提交、重复消息和重试最多发布一次；重转码及删除与修正互斥。
- 杜比视界源在页面及后端均拒绝旋转，现有原始播放源保护不被绕过。

## 接口与运维

- `POST /admin/videos/:id/rotation/preview`：传 `mode=auto|lossless|reencode`，返回当前文件版本、选用方式、原因及临时空间估计；不修改文件。
- `POST /admin/videos/:id/rotation`：传唯一 UUID `request_id`、`angle=90|180|270`、明确的 `mode`、预检 `version`；重编码还要求 `reencode_confirmed=true`。相同请求幂等返回原任务。
- `GET /admin/videos/:id/rotation`：返回最新任务。状态为 `queued/running/cleanup/succeeded/failed`；`cleanup` 表示新视频已发布但旧文件尚未清理完成，不得重做旋转。
- 所有接口沿用管理员鉴权。路径、文件大小及修改时间仅在服务端持久化，不通过作业 JSON 暴露物理路径。
- 迁移 `0049_video_rotation` 新增作业表及物理变更保护触发器。先执行迁移，再更新 API/worker 和管理端；worker 立即并每分钟恢复活动作业，队列仅负责唤醒。
- FFmpeg 需支持输入 `-display_rotation` 参数（FFmpeg 6 及以上）；当前已用本机 FFmpeg 8.1.2 验证。重编码沿用 macOS VideoToolbox，禁用静默软件编码回退。
- 已完成内容删除无法恢复旧视频。回滚程序前应等待所有修正和清理结束；若需撤销迁移，停用入口及 worker 后执行 down 迁移。未完成任务不能直接删表，否则会丢失清理恢复信息。

## 本地验证结果

- FFmpeg 真实合成样本：三个角度、带方向标记的反向操作、解码画面逐帧摘要方向对比、无损媒体流摘要不变、macOS VideoToolbox 重编码通过。
- 隔离 PostgreSQL 16：完整迁移、0049重复应用与撤销重建、重复请求、跨会话互斥、处理期间 ready、旧文件删除、手动封面保留、输入替换失败保护、发布后恢复与引用冲突清理重试通过；集成测试启用 Go race。
- 前端：组件交互与视频列表定向测试通过，管理端构建通过；Chrome 实际读取 H.264 样本确认无损标记将显示尺寸从 160×96 变为 96×160；浏览器使用隔离模拟接口验证实际详情入口、预检、确认、进度、完成提示和窄屏无溢出。浏览器模拟不替代真实 API 与真机播放验收。
- 独立评审修复清理队列恢复、手动封面来源、孤儿扫描快照误删、目录软链接、显示宽高、兼容元数据、精确缓存验证及旧详情保存覆盖等问题，复评无剩余阻塞。
- 竞态检查：服务集成及相关包通过。handlers 的既有并行测试会并发修改 Gin 全局模式，默认并行 race 检查触发已有数据竞争；以 `-race -parallel 1` 执行相关包完整检查通过，未改动无关测试。
- Go 全仓原始测试中，既有 `TestParseTVAPKMetadataParsesReleaseAPK` 因 APK versionCode 为 148 而夹具期望 121 失败；本功能未改动 APK。手机和 TV 未改源码，不升级 App 版本。

实际问题视频、手机、TV 及下载后外部播放器的现场播放验收仍待执行；尚未部署到生产环境。
