# 视频方向修正探索

状态：需求已确认，设计整理完成；尚未开始功能实现。

## 当前结论

服务器具备旋转视频画面的技术基础，当前没有管理员可用的旋转功能。已有异步转码链路可以加入 FFmpeg 旋转滤镜；本机以合成画面执行顺时针 90° 滤镜成功，但尚未验证完整产品链路及实际问题视频。

## 已核实事实

- 转码参数及滤镜入口位于 `pkg/ffmpeg/ffmpeg.go:59`、`:89`；当前没有旋转参数，已有缩放滤镜，后续需要组合滤镜顺序。
- 转码后会重新截图并探测宽高，见 `internal/services/transcode.go:150`；已有自定义封面是否保留需要另行定义。
- 当前重转码先把视频改为 `uploaded`，播放要求 `ready`，直接复用会暂时不可播放，见 `internal/handlers/admin.go:681`、`internal/handlers/video_source.go:111`。
- 原片可能被清理，重转码可退回现有播放文件，见 `internal/queue/tasks.go:309`、`internal/handlers/admin.go:1210`；重复旋转可能产生重复有损编码。
- 杜比视界原始播放源明确禁止重转码，见 `internal/handlers/admin.go:668`；不能默认普通旋转流程覆盖此类视频。
- 当前编码器使用 macOS VideoToolbox，见 `pkg/ffmpeg/ffmpeg.go:85`；部署支持范围不能泛化为任意服务器。
- 当前探测结构没有读取旋转标记；设计时须处理源文件旋转信息、FFmpeg 自动旋转与人工修正的组合。

## 已确认需求

- 管理员在管理端视频详情逐条选择顺时针 90°、180°、逆时针 90°。
- 服务器永久修正视频文件，全端播放和下载修正文件均生效。
- 为节省硬盘空间，成功修正后不保留旧播放文件及该视频独占的服务端原片恢复副本；不提供依赖旧文件的无损撤销。
- 空间策略见 [架构决定 0035](adr/0035-video-rotation-without-source-retention.md)。删除旧文件须在新文件校验及切换成功后执行，处理期间需要临时输出空间；失败时保留可用旧文件并清理半成品。不能把删除旧文件作为启动转码前腾空间的手段。
- 本地视频修正不等于删除 115 云端文件或共享导入来源；清理边界需要确保不影响其它资源。

- 旋转角度以操作时当前正确应用文件旋转标记后的显示画面为基准。
- 自动截图封面重新生成，自定义海报保留。
- 处理期间仍提供旧视频，成功后新打开的播放和下载使用修正文件，不主动中断已有播放会话。
- 首期排除杜比视界源，管理端禁用旋转并给出中文原因，后端也必须拒绝。

## 曾比较的方向

| 方向 | 效果 | 代价与限制 |
| --- | --- | --- |
| 服务器旋转画面并重新编码 | 各端使用修正后的文件，下载该文件也保留效果 | 处理耗时、临时空间与编码损失 |
| 修改文件旋转元数据 | 通常无需重新编码画面 | 各播放器是否遵从标记需要实测 |
| 保存角度并由客户端旋转 | 可快速改变播放显示 | 各端需适配，文件及外部播放器不自动改变 |

## 实施设计

以下是满足已确认需求的技术方案，接口细节在实现时依据现有模块结构落地。

### 操作与范围

- 管理端视频详情增加“修正方向”，支持顺时针 90°、180°、逆时针 90°，按钮含义与当前画面一致。
- 提交前说明需重新编码、成功后删除旧文件、无法无损撤销，显示任务进度与失败原因。
- 只接受已就绪且本地播放文件可用的普通视频；杜比视界源及无法明确探测的特殊源拒绝处理，不静默降低保真策略。
- 视频 ID、标题、合集、标签、收藏、观看进度和外置字幕关系保持；旋转不改变时间轴，不自动旋转字幕文字。
- 不新增客户端旋转功能或下载管理系统；已有播放文件的下载读取修正后的内容。设备已经下载、缓存的旧文件不会远程改写。

### 作业与并发

- 新增独立方向修正作业，复用现有队列、硬件编码和进度能力，不直接套用会把视频改为 uploaded/processing 的重转码入口；修正期间视频保持 ready。
- 固定本次作业输入为受理时的当前播放文件，而非旧原片，避免第二次修正回到原片基准。
- 作业持久化视频、操作者、相对角度、输入版本、唯一请求标识、输出路径、处理阶段与错误摘要。请求重放返回同一作业；同视频的不同修正并发请求返回冲突。
- 作业需与重转码、删除等会改写同一视频文件的操作互斥，锁不能仅依赖单进程内存。发布前校验输入版本及视频状态仍匹配，避免覆盖更新或复活已删除视频。
- 队列只负责唤醒，数据库中的作业阶段是恢复依据。切换后重试只继续清理，不再次把角度叠加到新文件。

### 文件处理与发布

1. 在输出所在文件系统预检可用空间，以预计输出大小加余量判断，不复制一份完整旧视频作为备份；处理时仍需容纳旧文件和新输出。
2. 探测当前播放文件的显示矩阵、宽高及兼容性，统一已有方向信息后施加人工旋转；避免 FFmpeg 自动旋转和手工旋转重复作用。输出移除已应用的旋转标记。
3. 输出到作业专属临时文件，旋转与缩放合并为滤镜链。优先维持当前播放文件的编码类型、分辨率等级和既有音轨；兼容音频尽量直拷，不因方向修正重新引入其它媒体转换。
4. 探测验证输出非空、时长合理、宽高与旋转一致、音视频可读取；基于新文件生成自动截图，自定义海报保持。更新主播放文件字节大小、宽高及兼容元数据。
5. 完成文件写入并发布到唯一新路径，在数据库事务中条件切换播放指针、自动截图指针及相关元数据，同时登记待清理路径；数据库和文件系统不能假设支持同一原子事务。
6. 切换成功后清理被替代的旧播放文件及该视频独占的服务端原片，修正失效的原片引用，防止以后重转码回到未修正内容；保留共享导入资源、云端文件、自定义海报和外置字幕。
7. 旧文件清理完成才显示整体完成；清理失败展示“画面已修正，旧文件清理待重试”，后台仅重试清理，不重新转码或回退新播放文件。

新输出采用唯一版本路径，避免原地覆盖正在读取的视频。已有打开的文件读取可继续，但跨发布时刻的新 Range 请求可能读到新版本；需校准媒体响应验证信息并验证各端重新加载行为，不能承诺所有播放器无缝跨版本续播。无论如何不主动向客户端发送停止播放命令。

播放文件与自动截图的缓存必须在发布后更新或失效，避免新会话长期看到旧画面；不删除旧文件作为无限期媒体版本兼容副本。

### 失败与恢复

| 场景 | 必须达到的结果 |
| --- | --- |
| 预检空间不足 | 拒绝启动并提示空间不足，旧文件仍可用 |
| 输出过程中磁盘写满、转码或校验失败 | 不切换播放指针，清理半成品并保留旧文件 |
| 文件已就绪但数据库切换失败 | 旧文件继续播放；根据持久化作业恢复发布或清理未引用的新输出 |
| 发布成功后进程崩溃 | 恢复到旧文件清理阶段，不再次旋转 |
| 旧文件删除失败 | 新视频继续可用，显示清理待重试，保留精确待清理路径 |
| 重复点击、重复投递、任务重试 | 同一请求最多发布一次；不得累积旋转角度 |
| 视频被删除或被其它操作更新 | 版本校验失败，停止发布并清理本作业输出 |

删除前必须确认文件位于允许的服务端存储范围、确属旧版本且未被任何当前播放引用；已经不存在视为清理成功。共享路径无法证明独占时保留并显式报告原因。已有打开文件描述符时，磁盘空间可能到读取结束后才实际释放。

## 验收清单

- 横向、竖向视频的三个角度均正确；90°/270° 后宽高相应交换。
- 带已有旋转标记的样本无二次旋转；连续两次顺时针 90° 等于相对最初显示画面旋转 180°。
- 管理端、手机、TV 和下载后外部播放均验证新文件方向；已缓存旧文件不作为服务端修正失败。
- 处理期间旧视频可打开，成功后新会话读取新文件；Range、缓存及重新加载行为验证通过。
- 自动截图更新、自定义海报保留，音画同步、视频时长和外置字幕时间轴正常。
- 成功后磁盘不保留旧视频及独占原片恢复副本；清理失败有明确状态且可恢复。
- 空间不足、转码失败、数据库切换失败、切换前后崩溃和清理失败均进行故障验证。
- 并发提交、重复消息和重试最多发布一次；重转码及删除与修正互斥。
- 杜比视界源在页面及后端均拒绝旋转，现有原始播放源保护不被绕过。
