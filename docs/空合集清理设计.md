# 空合集清理设计

## 状态

两轮需求选择均已由用户确认，设计已收口；待用户确认最终共同理解后开始功能实现。

## 已确认范围

- 管理后台图片合集和视频合集列表页分别增加“清理空合集”入口，各自仅清理对应类型。
- 清理覆盖对应类型的全部合集，包含启用和停用合集，不受分页、搜索或状态筛选限制；界面明确说明范围。
- 按实际成员关系判断是否为空；有成员即保留，不因转码失败、不可播放或停用而视为空。
- 无成员但仍被其他业务引用的合集跳过。

## 现有系统事实

- 两个页面分别为 `admin-web/src/views/ImageCollectionManage.vue` 和 `CollectionManage.vue`，默认仅显示启用合集并分页。
- 图片合集即使没有图片成员，也可能被视频兼容字段、视频与图片合集关系、视频合集与图片合集关系引用。
- 视频合集即使没有视频成员，也可能关联图片合集。
- 压缩包批次、文件、分组及工作台配置保存合集引用，其中存在无数据库外键保护的 JSONB 引用。
- 现有单项删除接口只删除合集并解除关联，不删除媒体；没有批量清理接口，也未保护上述所有引用。

## 引用保护

- 正式业务引用及所有仍保留的压缩包批次、文件、分组、工作台配置引用均阻止清理，包含已完成导入的历史配置。
- 不为清理而解除上述引用；没有实际成员但仍有引用的合集保留。

## 交互与执行

1. 点击“清理空合集”，预览对应类型全量可清理合集的数量；没有可清理项时直接提示。
2. 确认弹窗说明“将永久删除 N 个空合集”，明确不受当前筛选和分页限制，并说明不会删除图片、视频或媒体文件。
3. 用户确认后，仅处理本次预览的候选合集；预览后才变为空的其他合集不纳入本次执行。
4. 执行时再次检查实际成员与业务引用；候选中新增成员或引用的自动跳过，已经删除的候选不重复删除。
5. 永久删除符合条件的合集记录，不提供回收站，不触碰图片、视频或媒体文件。
6. 完成后显示实际删除数与跳过数并刷新列表；请求期间防止重复提交，失败时明确提示，不能误报成功。

## 实现与验收边界

- 复用现有管理员权限边界；前端不能用当前页结果自行判断全量候选。
- 预览候选与执行范围由服务端约束，并保护检查与删除之间的并发成员、引用写入；具体机制在实施时结合现有事务和写入路径选择。
- 定向覆盖两类合集、有成员、跨对象引用、历史配置引用、停用合集、跨分页筛选、无候选、预览后新增引用及重复执行场景。
- 本次仅涉及管理端、后端和文档，不修改手机或 TV 功能，因此不调整其版本号。
- 本文是需求设计，不表示功能已实现、已部署或已实际清理数据。
