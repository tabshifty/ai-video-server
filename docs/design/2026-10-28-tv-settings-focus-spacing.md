# TV 设置页底部间距与焦点可见性访谈

## 状态

用户回复“都按推荐来”，确认 Q1～Q3 的全部建议并授权实施。采用设置页全部操作项的浅色边框与提亮、已选时间保留金底、固定约 32dp 底部安全区。已完成实施与验证，TV 版本为 `0.1.149`（149）。

## 实施前已核实事实

- 设置页入口为 `android-tv-app/tv-app/src/main/java/com/chee/videos/feature/tv/TvCatalogScreen.kt` 中的 `TvHomeSettingsPanel`；包含账户操作、快进快退步长、剧集连播和屏保设置。
- 滚动容器已有 56dp 内容底部间距，外部另有 18dp 垂直间距。这不能证明遥控器自动滚动到最后一项时具有足够的可见底部空间；用户反馈仍需通过实际布局和设备验证定位。
- 屏保两组时间选项在 `TvScreensaverSettingsSection.kt` 中，聚焦仅放大到 1.04 倍；已选值使用暖金底色，二者语义不同。
- 共享 TV 焦点规则默认只缩放；侧边菜单和长视频播放器已有局部高亮例外。设置页若采用边框或提亮，应记录为明确的局部例外。
- 沿用已有领域词汇“屏保闲置等待时间”和“屏保单图停留时间”，避免用同一个“时间”混称两种配置。尚无需要新增的领域术语。

## 第一轮已确认决策

1. **Q1 优化范围**：设置页全部可操作项统一加强焦点反馈，覆盖账户操作、播放步长、连播开关、屏保开关和两组时间选项（已确认）。
2. **Q2 焦点与已选值**：聚焦时增加 2dp 高对比浅色边框并适度提亮，已选时间保持暖金底色。已选值和聚焦项可同时辨认，已选项再次聚焦仍有明显边框；方向键只移动焦点，按确认才修改值，禁用项不接收焦点。（已确认）。
3. **Q3 底部留白**：设置页始终保留约 32dp 底部安全区，自动滚动时聚焦项完整可见、焦点边框不裁切（已确认）。

## 决策树与后续

- Q1 确定适用范围，再核对范围内各类控件的一致性。
- Q2 确定焦点表现，再核对已选且聚焦、未选但聚焦、失焦和禁用四类状态。
- Q3 确定留白体验，再核对遥控器逐项下移、最后一项聚焦和滚动到底的实际布局。
- 用户已确认本轮全部推荐，决策树收口，按整体方案实施。
- 这属于可逆的局部视觉改动，当前无需 ADR。按仓库规则递增 TV 版本，更新根级 CONTEXT 与 plan，执行定向验证并提交。


## 实施与验证结果

- `TvHomeSettingsPanel` 在滚动视口外固定保留 32dp 底部安全区，保留原有 56dp 滚动内容末尾留白；焦点自动滚动时上下额外预留 8dp，避免放大后的焦点边框被视口裁切。
- `tvSettingsFocus` 仅供设置页使用，覆盖全部五类调用点：账户操作、播放步长、连播开关、屏保开关及屏保时间选项。白色 2dp 描边和中性 8% 提亮与原有缩放同时生效，暖金选中态继续保留，禁用项无焦点反馈。
- 设置面板可见性从 private 改为 internal，以便设备测试直接使用生产控件；同步修正三份现有源码检查的函数截取标记，避免检查越界。
- `:tv-app:testDebugUnitTest`：131 个测试类、651 项单测通过，失败、错误及跳过均为 0。
- `:tv-app:assembleDebug` 与 `:tv-app:assembleDebugAndroidTest` 通过，生成 ARM64 与 ARMv7 Debug APK。
- 新增 `TvSettingsFocusIntegrationTest`，在只读临时启动的 API 35 ARM64 模拟器、1920×1080 / 320dpi 视口运行通过：生产设置面板逐项遥控下移后控件完整可见且保持底部空间；末组时间聚焦后保留至少 32dp；由已选 10 分钟向右移动到 15 分钟不改变已选值，并通过截图像素验证焦点浅色边框实际绘制。截图人工检查确认焦点白边与已选金底可区分。
- 验证边界：模拟器使用手机系统镜像和 TV 逻辑视口，未安装或验证实体电视；测试直接挂载生产设置面板，未依赖真实服务器。构建仍有既有 compileSdk 35 与 AGP 8.5.2 版本提示。
