# PC 后台样式改版建议与实施交接

日期：2026-11-05。

状态：设计建议与实施交接文档。用户本轮要求生成文档，计划由其他 agent 实施；本文不代表已完成代码改造或运行验收。

## 一、目标与总体建议

将现有 PC 后台升级为简洁、紧凑、具有媒体特色的管理工作台，提升信息扫读、内容定位和高频维护效率。

推荐保留 Vue 3、Element Plus、Pinia、Vue Router、ECharts 以及现有 API 接入，采用渐进式改版。视觉参考 Shadcn Admin 的克制与层级，后台组织方式参考 Vue Pure Admin，并针对视频、图片、刮削和任务监控设计页面。

本轮推荐范围是公共视觉规范、导航归组、列表结构和详情信息组织。新增卡片视图、异常指标跳转等列为可选增强，不作为默认实施任务。

## 三、范围与兼容约束

### 3.1 推荐实施范围

- 公共颜色、文字、间距、边框、圆角、按钮和表格规范。
- 公共壳层与导航归组。
- 视频列表、任务监控、视频详情三个样板页面。
- 样板验收后，将已验证的模式推广到其他页面。

### 3.2 可选增强

以下项目涉及新增交互或功能，应另列范围、核查数据能力后实施：

- 图片、演员和合集的表格/卡片视图切换。
- 仪表盘异常指标跳转至对应筛选结果。
- 基于真实运维数据的待处理事项列表。
- 视频独立详情路由。
- 新的任务重试、取消或日志筛选能力。

### 3.3 非目标与必须保留的能力

- 本次样式改版不迁移前端框架、不引入整套后台模板、不修改数据库或后端业务语义。
- 保留现有路由地址、鉴权、管理员权限及 `{ code, msg, data }` 响应契约。
- 保留保存视图、筛选、排序、列设置、批量操作与详情编辑能力。
- 保留命令搜索、最近访问、导航展开和侧栏折叠偏好的兼容性；若变更分组键，明确迁移或回退策略。
- 保留任务与云下载的刷新周期、会话检测、扫码、失败提示、文件操作和异步清理行为。
- 深色主题已有变量，应防止本轮调整造成现有深色能力退化；新增主题切换器不在默认范围。
- 本次仅涉及管理端；不修改手机端或 TV 端版本号。

## 四、推荐视觉规范

以下数值为实施起点，可根据真实中文页面截图微调；确定后统一复用，避免每页另设标准。

| 项目 | 建议 |
| --- | --- |
| 整体配色 | 浅灰画布、白色内容区、现有蓝色主色；保留成功、警告、失败语义色 |
| 页面标题 | 22–24px，字重 600 |
| 区块标题 | 15–16px，字重 600 |
| 正文与表单 | 14px，优先中文系统字体，保留现有字体回退 |
| 次要信息 | 12–13px；不得通过过淡颜色牺牲可读性 |
| 关键数字 | 24–28px；需要比较的数字使用等宽数字 |
| 页面边距 | PC 以 20–24px 为起点，窄屏按现有断点收紧 |
| 间距体系 | 沿用现有 4px 基础间距，优先使用统一变量 |
| 圆角 | 控件 6–8px、主要容器 8–12px、浮层 12px 左右；相同组件保持一致 |
| 边框与阴影 | 卡片以细边框和留白区分；阴影重点用于抽屉、弹窗与浮层 |
| 动效 | 沿用约 120–240ms 的轻量反馈，避免悬停缩放导致布局跳动 |
| 操作层级 | 每页或独立操作区突出一个主要动作，其余使用次级、文字或更多菜单 |

当前区块标题与正文同为 14px，多个圆角级别同为 8px，可以通过上述规范增强层次。不要只增加圆角、阴影和留白，而使首屏可见数据明显减少。

## 五、页面改造建议

### 5.1 公共壳层与导航

推荐按工作目的归组，保留现有路由地址：

| 分组 | 页面归属建议 |
| --- | --- |
| 工作台 | 仪表盘与常用入口 |
| 内容管理 | 视频、待删除短视频、电视剧、演员、合集、图片、图片合集 |
| 采集与导入 | 上传、通用刮削、AV 手动刮削、论坛资源、115 云下载 |
| 任务与运维 | 任务监控；沿用系统设置页中的清理与日志入口 |
| 应用与系统 | 安装包、用户、系统设置 |
| 服务与工具 | IPTV、Telegram、工具箱 |

清理与日志目前位于系统设置页，不为凑齐导航而拆出新路由或重复列出同一整页；可先只在“应用与系统”保留系统设置入口。“服务与工具”保留为服务专用分组，避免与采集、任务混杂。

控制分组标题与菜单的视觉层级，当前项使用轻量底色和明确文字状态。保留命令搜索及最近访问，但应检查菜单重复后是否挤压主导航。

现有侧栏宽 224px，低于 1280px 自动折叠，低于 1024px 使用抽屉。先验证这些策略在实际内容中的表现，再决定是否调整，避免只根据模板截图改断点。

### 5.2 统一列表页结构

推荐顺序：页面标题与主操作 → 保存视图或状态切换 → 搜索与筛选 → 结果表格 → 分页。

- 全局头部保留位置导航与全局搜索；页面标题和页面操作只设一个主要呈现位置，避免重复堆叠标题。
- 搜索、筛选、排序、列设置应就近组织，避免用户在顶栏和正文间反复寻找。
- 简单列表只提供必要工具，不要求所有页面都增加保存视图或高级筛选。
- 保留已选条件的可见提示与清除入口，切换视图和分页行为遵守现有约定。
- 使用浅色表头、横向分隔与悬停反馈，优先减少纵向网格线。
- 操作区保持稳定；内容过宽时只让表格区域横向滚动，整页不被撑开。
- 加载、后台刷新、空库、筛选无结果、权限或请求失败应有不同表现，失败时不能伪装成空数据。

### 5.3 视频列表

- 将封面、标题和适量次要信息组织为一个媒体单元，缩短横向阅读距离。
- 状态、大小、时间等需要纵向比较的字段保留独立列；默认字段根据高频任务精简，其他字段通过现有列设置展示。
- 若合并或调整列定义，兼容已保存视图与列偏好，防止旧偏好导致核心字段消失。
- 常规操作展示“查看/编辑”及“更多”；危险操作保留已有确认与权限约束。
- 含图表格保留足够高度显示封面和两行信息，纯文本表格继续采用紧凑密度。
- 表格仍是默认维护视图；卡片视图作为后续可选增强。

### 5.4 视频详情

- 顶部集中展示封面、标题、状态和核心操作。
- 按“基本信息 / 文件与播放 / 字幕 / 处理记录”等职责组织标签页；以实际已有数据为准，不创建没有内容的标签页。
- 频繁编辑继续使用抽屉，底部固定保存与取消操作；预留内容底部空间，避免遮挡最后字段。
- 切换标签时保留未保存输入，防止组件卸载造成编辑丢失；提交成功、失败、关闭与重新打开遵循原有状态重置语义。
- 日志、字幕、文件等独立操作保留自己的加载与错误反馈，避免一个区域失败阻塞全部详情。
- 独立详情路由留作后续选项，不与本轮样式重整捆绑。

### 5.5 任务监控与云下载

- 统一状态标签、进度条、错误摘要和更新时间的展示规则；状态由文字与颜色共同表达。
- 运行、等待、成功、失败的表现应便于扫读；异常行使用局部强调，避免大面积红底。
- 长错误在列表中显示摘要，并提供可聚焦、可复制完整信息的入口。
- 自动刷新保留当前筛选、页码及阅读位置；后台刷新避免反复清空列表或整表闪烁。
- 展开详情、更多操作和重试入口的位置保持一致；只呈现现有接口支持的操作。
- 云下载的登录、会话失效、扫码和文件删除等现有状态必须回归验证，不能在视觉调整中简化掉。

### 5.6 仪表盘

- 优先展示可用于判断运行状况的已有指标，其次展示库存与趋势。
- 常用入口采用轻量排列，不以大块装饰卡片挤压主内容。
- 趋势图统一标题、图例、颜色与空态，保留现有数据缺失提示。
- 异常任务入口和指标跳转归入可选增强；缺少接口数据时明确留空或隐藏，不能编造指标。

### 5.7 设置、日志与其他页面

- 设置页按真实职责分区，清理操作与日志阅读保持明确分隔；危险或有副作用的操作保留说明与确认。
- 日志区保留等宽字体、滚动边界和文本复制能力，不为视觉统一而改成难以阅读的普通卡片文字。
- 图片、演员、合集等页面先统一公共样式，再评估卡片视图的收益与范围。
- 对未纳入首轮深度改版的页面做公共样式兼容走查，尤其是复杂表单、工具箱与地图类专用界面。

## 六、实施顺序与交付物

### 阶段一：基线与公共规范

1. 读取当前适用 `AGENTS.md`，检查工作区，确认现有路由、主题、偏好和测试。
2. 在 `plan.md` 追加本次实施计划。
3. 为三个样板页记录当前截图、首屏结构、主要操作与关键状态。
4. 统一主题变量、公共组件、按钮和表格规范，再调整导航归组。
5. 走查其他页面是否受到全局样式误伤。

交付物：视觉规范、公共层变更、导航变更、同尺寸前后截图、阶段验证结果。

### 阶段二：三个样板页面

按视频列表 → 任务监控 → 视频详情推进。先完成一个页面的视觉与交互验证，再复用到下一个。避免多个页面同时各自设计一套模式。

交付物：三个样板的代码、必要回归测试、正常/空态/失败/加载截图，以及保留能力的验证记录。

### 阶段三：推广与收尾

将样板规范推广到云下载、仪表盘、用户、设置及其他受影响页面；记录需要单独立项的可选增强，不在收尾时临时扩展功能。

按仓库规则追加 `plan.md`；若实现形成长期有效的界面或兼容约定，追加根级 `CONTEXT.md`。使用中文小范围提交，保证各阶段可回退。

## 八、给实施 agent 的起始说明

先以当前源码和运行页面复核本文基线，再实施公共规范与三个样板。已存在的能力直接复用，不重复建设。布局与样式参数可在本文建议区间内据实调整；涉及新增接口、独立详情路由、视图模式或业务操作时，应单独说明范围，不将可选增强自动纳入本轮。

本文件用于交接建议，不属于 `tasks/` 任务完成标记；不得因为读完本文就宣称功能完成。完成代码、定向验证与浏览器走查后，向用户提供具体结果及剩余限制。
