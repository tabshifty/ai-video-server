# 压缩包分组桌面化需求访谈

日期：2026-11-09。状态：需求已确认，尚未实施。以下最终需求及验收清单优先于历史访谈记录；首轮多分组决定已撤销。

## 最终需求与验收清单

- [ ] 右侧是平级文件夹网格，显示名称、成员数和处理状态；支持新增、右键及可见操作菜单。双击打开成员列表，顶部提供返回、编辑和入库，不常驻复杂属性表单。
- [ ] 每组独立保存显示名称、标题模式与标题、描述、标签、视频类型、视频合集和图片合集。保留统一标题与按文件名模式、单文件显式内容覆盖优先、图片默认文件名规则；单文件不再覆盖两类合集。
- [ ] 每文件最多一个组，允许未分组。多选拖入或按钮加入均为换组，同组去重；拖入目录递归处理文件。未入库文件换组后采用新组配置并保留显式内容覆盖。
- [ ] 已入库文件允许换组，正式媒体元数据及历史关系保持不变，新组显式入库时只补关系。排队或处理中文件禁止换组。
- [ ] 上传配置是新建组初始模板，创建后独立；取消特殊主组及父子继承。新包按媒体目录自动生成平级组，重名以路径区分；根目录直属文件归普通可删除组，默认以上传标题命名。
- [ ] 新建组不自动创建正式合集，两类合集支持多选已有或当场新建。有视频必须选视频合集，有图片必须选图片合集；两类都选才两两追加关联，包含合集原有成员，不清除既有关系；提交前展示范围。
- [ ] 拖入仅保存整理草稿，显式入库固定成员与配置后由后台执行。执行中的组锁定配置、成员及删除，其他组可整理；失败只重试未完成部分，离开或刷新不取消。
- [ ] 媒体只创建一份，命中已有媒体不覆盖元数据；新增目标合集可再次入库补关系，取消目标合集不撤销正式关联。显示待入库、待补充关联、处理中、已完成和有失败状态。
- [ ] 删除组或移出成员不删除源文件与正式数据，删组成员回未分组。空组可保存不能入库；未分组须先建组或加入组，全部入库仅处理真实组并提示未分组数量。
- [ ] 旧树形组转换为平级并保存转换前有效配置与成员，同名以旧路径区分；原主组成为普通组，文件级合集差异按相同配置拆成独立组，保持原目标。活动任务完成后再转换，不改变执行快照。
- [ ] 分组属于压缩包批次的临时整理资源。删除压缩包批次时清理该批次分组、成员归属及工作区草稿，不遗留可访问的孤立组；已经入库的媒体、正式合集和合集关联保留。排队或执行中的批次继续拒绝删除。

本文将“压缩包被执行删除”落实为管理端压缩包批次删除动作；不将外部人工移除源文件解释为自动删除正式媒体或触发批次删除。

## 交付边界

本次涉及管理端与后端工作台、批次草稿兼容和合集关联；左侧目录导航继续沿用默认收起与完整路径面包屑。手机及 TV 展示不在本次范围。当前仅完成需求与领域决策记录，没有修改业务代码。

## 访谈历史

以下保留每轮决策过程，其中已撤销的多组引用及冲突选择不作为验收依据。

## 用户明确提出的目标

- 右侧分组采用桌面文件夹布局，简化常驻操作。
- 支持新增、删除；每组拥有自己的标题、描述、标签、合集等配置。
- 分组右键提供编辑、删除及入库。
- 同一文件可以加入多个分组。
- 分组主要负责视频合集和图片合集的组织：视频进入视频合集，图片进入图片合集，两类合集自动关联。

## 既有约定与新目标的冲突

现有 ADR 0032 和 2026-10-26 需求定义文件单分组归属、父子组继承、唯一主分组及成功成员冻结。多分组要求已明确替代单分组限制，其余规则需要结合新交互重新确认，不能沿用旧文档推定本轮答案。

## 首轮待决分支

1. 多组元数据不同：复用单一媒体并追加关系，还是产生独立媒体记录；新增媒体的标题等字段如何确定。
2. 分组层级：平级桌面文件夹，还是继续允许嵌套及父组继承。
3. 合集配置：手动选择已有或新建，还是每组自动配套创建。
4. 自动关联：视频合集与图片合集全量配对时，对合集原有成员的影响范围。
5. 生效时机：拖入仅保存整理，还是立即执行入库和关联。

## 后续依赖分支

待首轮确认后，再收口成功媒体追加分组、删除或移出成员的影响、配置变更与再次入库、主分组及旧批次兼容、入库状态与错误恢复、桌面交互细节。

## 首轮已确认决策

用户确认五项建议，并明确保留统一标题与按文件名标题规则。

1. 媒体只入库一份，多个分组累加合集关系；首次成功入库确定媒体元数据，后续分组入库只追加关系，不覆盖已有信息。全部入库遇到同文件元数据冲突，提交前选择采用哪组配置。
2. 分组改为平级、独立配置，取消父子分组及继承；以文件夹图标、名称、成员数和状态呈现，双击打开，右键及可见菜单提供操作。
3. 两类合集均可多选，支持选择已有合集或当场新建；创建分组不自动创建正式合集。
4. 入库时，本组选中视频合集与图片合集全部两两追加关联，对合集整体生效，包含已有成员；提交前展示范围。
5. 拖入仅保存整理，显式入库才创建媒体和关联；拖入另一组增加引用，同组重复加入去重。
6. 保留“统一标题／按文件名”选择；沿用既有视频标题策略、图片默认文件名及单文件显式标题优先规则。

## 代码核对结论

- 当前文件归属为单个 group_id，分组支持父链解析；需要改为多分组成员关系及按组解析配置。
- 当前成功文件冻结且提交时直接跳过，不能直接实现成功文件加入另一组后追加合集关系。
- 已有媒体仓储支持追加所属合集及视频到图片合集关系；工作台未自动创建视频合集到图片合集的关系。现有合集关联替换接口不能直接用于新流程，自动关联必须保留历史关系。
- 后台作业使用不可变配置快照，应继续区分草稿编辑与已提交执行。

## 第二轮待决问题

- 已入库文件加入另一组、配置修改后的补充入库与完成状态。
- 删除分组及移出成员是否仅删除草稿引用。
- 主分组、未分组及旧树形批次的兼容方式。
- 集合为空时的入库校验及缺少一类合集时的行为。
- 跨组冲突选择、成员查看与编辑入口。
- 排队和处理中成员的编辑边界。

## 第二轮确认与首轮修正

用户明确取消单文件进入多个分组，其余建议采用。本节替代首轮多分组决定及其派生冲突规则。

- 同一文件最多属于一个分组，也允许未分组；取消多组元数据冲突选择。跨组操作与成功文件边界待下一轮确认。
- 保留媒体只入库一份。分组新增合集可再次入库补充关系，取消旧合集选择不撤销正式历史关联，已入库媒体的元数据不覆盖。
- 删除分组或移出成员只修改整理关系，不删除源文件、正式媒体、合集和历史关联；删除组后成员回未分组。
- 取消特殊不可删除主分组，上传配置作为新建分组的初始模板，各组之后独立编辑；未分组不承担配置继承。
- 有视频必须至少选一个视频合集，有图片必须至少选一个图片合集；两类都选时才两两关联。纯视频或纯图片组不强制另一类合集；空组可保存不可入库。
- 双击打开组成员列表，顶部返回、编辑和入库；右键与可见菜单提供操作。支持多选拖入、按钮加入与组内多选移出，目录递归处理并去重。
- 提交固定成员和配置，后台持续执行；执行中的组禁止改配置、增删成员或删除，其他组仍可整理；失败只重试未完成部分，刷新离开不取消。
- 继续保留统一标题或按文件名、单文件显式标题优先及图片默认文件名规则。

## 当前剩余待决边界

## 第三轮确认及批次删除补充

用户确认 Q13～Q17 推荐，补充“压缩包被执行删除后，分组没有存在必要”。最终单组移动、平级初始化、旧批次转换、分组统一管理合集及未分组先归组再入库规则已收口；分组生命周期随所属批次结束，正式媒体与合集独立保留。

代码事实：当前 DeleteBatch 在批次事务锁下拒绝活动作业，然后删除批次；工作区及旧分组外键均带批次删除级联。后续实现应沿用这一生命周期并验证新结构没有遗漏。
