# 压缩包分组桌面化需求访谈

日期：2026-11-09。状态：访谈中，仅记录新目标与待决问题，尚未授权按未确认细节实施。

## 用户明确提出的目标

- 右侧分组采用桌面文件夹布局，简化常驻操作。
- 支持新增、删除；每组拥有自己的标题、描述、标签、合集等配置。
- 分组右键提供编辑、删除及入库。
- 同一文件可以加入多个分组。
- 分组主要负责视频合集和图片合集的组织：视频进入视频合集，图片进入图片合集，两类合集自动关联。

## 既有约定与新目标的冲突

现有 ADR 0032 和 2026-10-26 需求定义文件单分组归属、父子组继承、唯一主分组及成功成员冻结。多分组要求已明确替代单分组限制，其余规则需要结合新交互重新确认，不能沿用旧文档推定本轮答案。

## 首轮待决分支

1. 多组元数据不同：复用单一媒体并追加关系，还是产生独立媒体记录；新增媒体的标题等字段如何确定。
2. 分组层级：平级桌面文件夹，还是继续允许嵌套及父组继承。
3. 合集配置：手动选择已有或新建，还是每组自动配套创建。
4. 自动关联：视频合集与图片合集全量配对时，对合集原有成员的影响范围。
5. 生效时机：拖入仅保存整理，还是立即执行入库和关联。

## 后续依赖分支

待首轮确认后，再收口成功媒体追加分组、删除或移出成员的影响、配置变更与再次入库、主分组及旧批次兼容、入库状态与错误恢复、桌面交互细节。

## 首轮已确认决策

用户确认五项建议，并明确保留统一标题与按文件名标题规则。

1. 媒体只入库一份，多个分组累加合集关系；首次成功入库确定媒体元数据，后续分组入库只追加关系，不覆盖已有信息。全部入库遇到同文件元数据冲突，提交前选择采用哪组配置。
2. 分组改为平级、独立配置，取消父子分组及继承；以文件夹图标、名称、成员数和状态呈现，双击打开，右键及可见菜单提供操作。
3. 两类合集均可多选，支持选择已有合集或当场新建；创建分组不自动创建正式合集。
4. 入库时，本组选中视频合集与图片合集全部两两追加关联，对合集整体生效，包含已有成员；提交前展示范围。
5. 拖入仅保存整理，显式入库才创建媒体和关联；拖入另一组增加引用，同组重复加入去重。
6. 保留“统一标题／按文件名”选择；沿用既有视频标题策略、图片默认文件名及单文件显式标题优先规则。

## 代码核对结论

- 当前文件归属为单个 group_id，分组支持父链解析；需要改为多分组成员关系及按组解析配置。
- 当前成功文件冻结且提交时直接跳过，不能直接实现成功文件加入另一组后追加合集关系。
- 已有媒体仓储支持追加所属合集及视频到图片合集关系；工作台未自动创建视频合集到图片合集的关系。现有合集关联替换接口不能直接用于新流程，自动关联必须保留历史关系。
- 后台作业使用不可变配置快照，应继续区分草稿编辑与已提交执行。

## 第二轮待决问题

- 已入库文件加入另一组、配置修改后的补充入库与完成状态。
- 删除分组及移出成员是否仅删除草稿引用。
- 主分组、未分组及旧树形批次的兼容方式。
- 集合为空时的入库校验及缺少一类合集时的行为。
- 跨组冲突选择、成员查看与编辑入口。
- 排队和处理中成员的编辑边界。
