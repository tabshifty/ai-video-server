# 压缩包全屏入库工作台需求访谈

日期：2026-10-26。状态：访谈中，尚未形成经用户确认的实施方案。本文区分用户已明确要求、现有系统事实与待决问题；建议不视为已经接受的决策。

## 用户已明确的要求

- 上传压缩包后的操作改为全屏工作区，取代抽屉弹窗。
- 左侧模拟文件管理器，提供右键操作；文件整理只改变模拟关系，不实际改动原有物理文件。
- 右侧为入库分组，允许创建、删除，也能按文件夹默认创建。
- 分组具有默认标题、标签、视频合集和关联图片合集；关联图片合集可多选，视频合集和图片合集均可在操作中创建。
- 分组默认继承父分组；主分组的具体规则由用户后续说明，本轮不预设。
- 标题策略能够切换为按文件标题录入。
- 左侧文件可拖入右侧分组；视频进入视频合集，图片进入关联图片合集，支持批量操作。

## 已核实的现状与冲突

- `internal/models/models.go` 的 `ArchiveImportGroup` 暂无父分组标识；现有分组是平级关系。现有继承是批次默认值、分组默认值、文件字段覆盖，并非分组树继承。
- 文件目前只有一个分组归属。新增多分组引用会改变现有关系，必须明确选择。
- `CONTEXT.md` 的既有词条将视频关联图片图集限制为一个；代码中单文件编辑和入库已存在多选支持，但部分分组和批量路径仍调用单选校验。本次需明确统一的多选语义与覆盖范围。
- 既有词条记载文件初始未分组、分组单媒体类型；当前解压代码已按直接目录生成分组并支持混合媒体，文档与代码存在差异，不把历史词条直接当作本次需求。
- 现有文件名派生标题、原标题转存描述、已入库文件冻结等规则均需在后续访谈确认保留范围。

## 决策树与首轮待决问题

1. 全屏形态：独立页面还是全屏对话框；是否保留应用导航。
2. 虚拟文件操作：右键菜单需要哪些动作，是否包含新建目录、改名、移动、复制、排除和恢复。
3. 拖入分组的关系：单一归属还是多处引用；是否接受视频与图片混合的分组。
4. 分组树与目录树：右侧是否独立维护父子关系，按目录创建时是否保留完整层级，之后是否联动左侧目录调整。
5. 继承语义：逐字段动态继承还是创建时复制；空值、显式清空与标签集合怎样处理。
6. 合集多选的业务边界：视频合集是否也可多选，图片是否写入所有选中图集，视频是否关联所有选中图集。
7. 标题模式：统一标题与文件名标题作用于哪些媒体，虚拟改名是否影响入库标题；旧标题转存描述规则留待模式确定后继续确认。
8. 入库时机：拖拽仅整理待提交配置还是立即执行正式入库；提交范围、部分失败与重试规则留待执行方式确定后展开。
9. 草稿生命周期：刷新、离开与重开后是否恢复工作区；新建正式合集的生效时机留待草稿边界确定后展开。
