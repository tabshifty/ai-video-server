# 115 开放平台接入

## 信息源

- 把 [115 开放平台官方语雀文档](https://www.yuque.com/115yun/open) 作为接口事实的唯一主来源。
- 先读 [references/official-doc-index.md](references/official-doc-index.md) 定位文档，涉及授权或令牌时再读 [references/authentication.md](references/authentication.md)。
- 实现前打开相应官方页面，核对路径、方法、Content-Type、必填参数、响应字段和更新时间。本 Skill 只是导航与稳定契约摘要，不是官方文档镜像。
- 官方文档与仓库示例冲突时，以官方文档为准，并记录核对日期。

## 工作流程

1. 确认应用形态、是否有可保密的服务端，以及在 `open.115.com` 审核通过的应用资料。
2. 选择授权方式：有服务端且可保密 `client_secret` 时使用授权码模式；无后端客户端使用手机扫码 PKCE 模式。
3. 在官方文档中定位所需接口，逐项记录 HTTP 契约，不根据类似接口猜测字段。
4. 实现最小客户端边界：授权、令牌存储/刷新、Bearer 请求、错误归一化、频控退避。
5. 对删除文件、清空回收站、删除/清空云下载任务等破坏性操作增加明确确认、审计与最小权限。
6. 用测试服务器或可控账号验证成功、授权拒绝、令牌过期/旋转、频控、网络超时和部分成功。

## 安全与可靠性

- 不要收集 115 账号密码，不要从非官方工具复用或抓取用户令牌。
- 不要把 `client_secret`、`access_token`、`refresh_token`、授权码或下载直链写入日志、URL、前端持久化、代码仓库或错误响应。
- 服务端加密或借助密钥管理系统保存令牌；令牌文件至少限制为当前运行用户可读写。
- 每次刷新同时持久化服务端返回的新 `access_token` 和新 `refresh_token`；使用原子替换和单航刷新，避免并发刷新覆盖旋转后的令牌。
- 使用响应中的 `expires_in` 计算到期时间，预留时钟偏差；不硬编码示例有效期。
- 官方未公开频控细则。限制并发，优先缓存可缓存结果，对明确可重试的失败使用有上限的指数退避和抖动，不要高频刷新令牌。
- 不要默认重试非幂等写操作。需要重试时，先根据查询接口确认服务端状态。

## 仓库内参考

- `docs/examples/115LocalNatManager` 可用于理解令牌刷新、文件 API 和云下载调用链，但不把它视为安全或可投产的基线。
- 复用前必须重新评审绑定地址、本地 API 鉴权、CORS、令牌文件权限、下载目录穿越、HTTP 状态码检查、断点续传与测试覆盖。

## 交付检查

- 在设计或实现说明中列出本次使用的官方文档直达链接和核对日期。
- 明确授权模式、凭证保密边界、回调白名单和 `state`/PKCE 校验。
- 覆盖令牌旋转、过期偏差、并发刷新和授权撤销/失效后的重新授权路径。
- 明确资源 API 的域名、方法、参数编码、分页、错误映射、频控与破坏性操作保护。
