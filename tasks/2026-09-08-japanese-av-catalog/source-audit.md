# 日本 AV 元数据来源准入台账

> 状态：初始审计。本文区分“代码存在解析器”和“来源允许长期目录采集”，前者绝不自动推出后者。

## 准入状态

| 状态 | 含义 |
|---|---|
| 候选 | 只记录名称，尚未核对政策 |
| 待证据 | 已开始核对，但缺少足以批准的条款、API 或书面授权依据 |
| 已批准 | 允许的字段、保存期限、图片策略、频控和停止条件均有可复核依据 |
| 已拒绝 | 明确禁止、要求绕过控制、无法保证内容合法性或与产品边界冲突 |
| 已暂停 | 曾批准，但政策、页面结构、错误率或访问状态变化，停止调度等待复核 |

只有“已批准”来源能进入生产调度。`robots.txt` 是必要检查项之一，但不是版权许可、数据库使用许可或再展示授权。

实现时“准入状态”和“运行状态”必须分开保存：已暂停是运行状态，不自动抹掉历史批准证据；如果暂停原因是政策变化，准入状态同时回到“待证据”。

## 每个来源必须记录

- 来源所有者、正式域名、访问方式和联系人或停止渠道。
- 服务条款、API 条款、`robots.txt` 的核对 URL、日期和原文摘要。
- 允许采集的字段、请求路径、保存期限、是否允许派生翻译和跨来源合并。
- 封面及样例图片是否允许下载、缓存、裁剪和再次展示。
- 认证方式、频率限制、并发限制、建议 User-Agent 和退避要求。
- 成年内容保证、下架或纠错机制、数据删除要求和政策复查周期。

## ThePornDB OpenAPI 审计

2026-09-08 对官方 `https://api.theporndb.net/docs` 及其引用的 `https://api.theporndb.net/specs?openapi.json` 做了只读检查，没有携带 Token，也没有调用目录数据接口。

- OpenAPI 版本为 `3.0.0`，服务版本标记为 `v3.24.747`，全局认证是 `Authorization: Bearer <token>`。
- 规范包含 42 条路径；与本任务直接相关的读取接口包括 `GET /jav`、`GET /jav/{identifier}`、`GET /changes/{type}`、演员、站点、标签和导演接口。
- `GET /changes/{type}` 支持 `type=jav`、`from` 时间、`page` 和 `per_page`，适合作为增量变化源；普通分页与变化分页的 `per_page` 最大值均为 100。
- `SceneResource` 提供标题、`external_id`、简介、日期、时长、SKU、多尺寸图片、创建时间、最后更新时间、演员、站点、标签、导演和外部链接，覆盖本任务大部分字段。
- 规范没有 `termsOfService`、`license`、限速说明、响应限速头、缓存期限、署名要求或图片再展示授权；只定义了通用 `403`、`404`，没有声明 `429` 契约。
- `https://theporndb.net/terms` 与 `/privacy` 返回 `404`；登录页公开配置显示未启用 Terms/Privacy 功能，并提供 `admin@theporndb.net` 联系方式。

结论：技术能力适合作为首个 API 试点，但法律与运营证据仍不完整。只有取得 API 数据长期保存、图片缓存/展示、调用频率和下架处理的明确答复后，才能从“待证据”升级为“已批准”。

## 当前门禁结论

- 当前没有“已批准”来源，因此不得开始全量或周期抓取。
- 首选下一步是由用户提供计划使用的具体网站、已有 API 资格或授权条件，再逐个完成政策证据。
- ThePornDB 若作为首期候选，需要由用户通过其正式联系渠道取得并保留授权答复；本项目不会代替用户发送外部申请。
- 若首期只为家庭私有本地媒体补元数据，仍不能跳过来源条款；使用范围只影响风险和数据展示范围，不改变来源许可要求。
