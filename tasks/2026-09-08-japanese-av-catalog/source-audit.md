# 日本 AV 元数据来源准入台账

> 状态：初始审计。本文区分“代码存在解析器”和“来源允许长期目录采集”，前者绝不自动推出后者。

## 准入状态

| 状态 | 含义 |
|---|---|
| 候选 | 只记录名称，尚未核对政策 |
| 待证据 | 已开始核对，但缺少足以批准的条款、API 或书面授权依据 |
| 已批准 | 允许的字段、保存期限、图片策略、频控和停止条件均有可复核依据 |
| 已拒绝 | 明确禁止、要求绕过控制、无法保证内容合法性或与产品边界冲突 |
| 已暂停 | 曾批准，但政策、页面结构、错误率或访问状态变化，停止调度等待复核 |

只有“已批准”来源能进入生产调度。`robots.txt` 是必要检查项之一，但不是版权许可、数据库使用许可或再展示授权。

## 每个来源必须记录

- 来源所有者、正式域名、访问方式和联系人或停止渠道。
- 服务条款、API 条款、`robots.txt` 的核对 URL、日期和原文摘要。
- 允许采集的字段、请求路径、保存期限、是否允许派生翻译和跨来源合并。
- 封面及样例图片是否允许下载、缓存、裁剪和再次展示。
- 认证方式、频率限制、并发限制、建议 User-Agent 和退避要求。
- 成年内容保证、下架或纠错机制、数据删除要求和政策复查周期。

## 现有代码来源盘点

`newAVCrawlerProvider` 当前注册 35 个抓取器，其中默认启用 15 个。它们共用 `SearchCandidates` 和 `FetchByDetailURL` 两个单片接口，没有列表发现、增量游标或目录更新时间接口。

默认启用来源：`theporndb`、`dmm`、`javdb`、`jav321`、`mgstage`、`javbus`、`javlibrary`、`airav_cc`、`avsex`、`getchu`、`mywife`、`fc2ppvdb`、`fc2club`、`fc2`、`fc2hub`。

其余已注册来源：`cableav`、`hdouban`、`hscangku`、`iqqtv`、`7mmtv`、`prestige`、`xcity`、`airav`、`avsox`、`freejavbt`、`madouqu`、`mdtv.com`、`cnmdb`、`faleno`、`fantastica`、`giga`、`javday`、`kin8`、`love6`、`lulubar`。

从现有域名和适配逻辑看，可优先调查片商、零售平台或正式元数据 API；聚合站、镜像站和域名频繁变化的来源不应作为长期目录的首个权威来源。该分类只是调查优先级，不是授权判断。

## 当前门禁结论

- 当前没有“已批准”来源，因此不得开始全量或周期抓取。
- 首选下一步是由用户提供计划使用的具体网站、已有 API 资格或授权条件，再逐个完成政策证据。
- 若首期只为家庭私有本地媒体补元数据，仍不能跳过来源条款；使用范围只影响风险和数据展示范围，不改变来源许可要求。
