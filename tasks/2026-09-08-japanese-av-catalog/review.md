# Review 草案：日本 AV 元数据目录

> 状态：需求访谈中。以下门禁会随 PRD 决策继续细化。

## A. 设计门禁

- [ ] 产品范围、使用范围、首批来源和目标规模已明确。
- [ ] 每个来源的自动访问、字段保存、图片缓存和再展示边界已有可复核记录。
- [ ] 目录条目与本地 `videos` 的关系、主身份和去重规则已通过 ADR 固定。
- [ ] 字段冲突、人工覆盖、来源下架、演员归并和历史审计规则已明确。
- [ ] 不涉及未成年内容、访问控制绕过、视频正文或下载资源采集。
- [ ] `source-audit.md` 中至少一个来源达到“已批准”，并附可复核的条款、API 或书面授权依据；仅有 `robots.txt` 允许不能通过门禁。

## B. 试点来源验收

- [ ] 目录发现与详情解析均使用离线夹具覆盖正常、缺字段、结构变化和错误页面。
- [ ] 同一来源条目重复运行不会重复建档，内容未变化不会重复写入。
- [ ] 限速、并发、超时、有限重试、熔断、暂停和断点续跑均可测试。
- [ ] 每个合并字段能追溯来源、来源条目、抓取时间和原始值。
- [ ] 人工修改不会被后续同步静默覆盖。
- [ ] 来源状态不是“已批准”、缺少有效游标或已有活动运行时，调度入口均拒绝创建任务。
- [ ] 单页持久化故障不会推进游标；重放同一页不会重复建档、重复人物关系或重复图片记录。

## C. 数据与回滚

- [ ] migration 满足前向兼容契约，并验证 up/down 或等价回退路径。
- [ ] 来源停用不会删除其他来源事实或人工确认数据。
- [ ] 错误归并可拆分，错误抓取批次可定位并回滚。
- [ ] 图片删除、缓存过期和来源下架策略可执行且有审计。
- [ ] 上一版本 Go 二进制可以在新 schema 上继续启动和处理原有业务；新增目录表不反向改变 `videos`、`actors` 或既有刮削状态机。

## D. 运行验证

- [ ] 定向 Go 测试、全仓 Go 测试、`go vet ./...` 和管理端构建通过。
- [ ] 小规模试运行未超过来源限速，失败率、重复率和字段完整率达到 PRD 阈值。
- [ ] 人工抽样核对番号、标题、演员、分类、简介和封面，记录误差与处理结论。
- [ ] `git diff --check` 与 Markdown U+FFFD 乱码扫描通过。
