# Implement 草案：日本 AV 元数据目录

> 状态：需求访谈中。关键决策完成前只允许调研和文档更新，不进入代码实施。

## 阶段 0：来源与合规清单

- 明确产品使用范围、首批来源和预期规模。
- 为每个来源记录访问方式、授权或条款依据、`robots.txt`、允许字段、图片政策、频控、认证需求和退出机制。
- 任何需要绕过访问控制或无法确认成年内容边界的来源直接排除。
- 来源只有进入“已批准”状态后才能创建运行配置和调度任务；代码中已有解析器不构成批准依据。

## 阶段 1：领域模型与 ADR

- 决定“外部目录条目”和现有 `videos` 是否分离。
- 定义影片身份、发行版本、来源事实、演员身份、分类词表、图片资产、人工覆盖和本地视频关联。
- 定义字段级合并规则、数据血缘、软删除、重抓和历史审计。
- 把不可轻易逆转的选择写入新 ADR，把稳定术语追加到 `CONTEXT.md`。

## 阶段 2：最小来源适配器

- 只选择一个访问条件明确、数据质量稳定的来源作为试点。
- 把目录发现、详情读取、字段解析和图片处理拆成可测试接口。
- 使用固定 HTML 或 API 响应夹具做解析测试；测试不得依赖真实网站在线状态。
- 建立全局限速、来源级并发、超时、重试上限、熔断和可识别的 User-Agent。

## 阶段 3：持久化与幂等同步

- 新增前向兼容 migration、仓储和服务层。
- 以来源条目 ID 保证采集幂等，以规范化业务身份执行跨来源候选归并。
- 保存字段来源、抓取时间和内容指纹；人工覆盖与来源事实分层存储。
- 支持游标或时间窗口断点续跑，不使用只存在内存中的页码状态。
- 每页来源事实写入、运行计数和游标推进必须在同一数据库事务内完成；事务失败时整页重放。

## 阶段 4：长期调度与运维

- 增加增量采集任务、失败重试、来源健康状态和可暂停开关。
- 防止任务重叠、无限重试和来源故障造成队列堆积。
- 提供管理端冲突审核、手动重抓、合并与拆分、来源禁用和审计查看。
- `401/403`、政策页变化或成年内容保证失效必须自动暂停来源；`429` 遵循 `Retry-After`，网络错误和 `5xx` 只做有上限的抖动退避。

## 阶段 5：扩展来源

- 每次只增加一个来源，先补访问清单、解析夹具、字段映射和限速配置。
- 通过试点数据质量门槛后才进入常态调度。
- 来源结构或政策变化时可单独停用，不影响其他来源和已确认数据。

## 暂不确定的实现选择

- 调度继续使用 Asynq，还是独立运行目录采集器进程。
- 图片由现有媒体存储承载，还是引入独立对象存储和版权保留策略。
- 原始响应只保存内容指纹和规范化字段，还是短期保存经过清理的快照用于解析回归。
- 演员复用现有 `actors` 表，还是先建立外部演员身份再与内部演员归并。

## 当前推荐顺序

1. 用户确认目录范围与使用范围。
2. 用户给出首批来源清单和已有 API、授权或账号条件。
3. 完成逐来源条款与图片政策核对，只选择一个已批准来源。
4. 接受或否决提议中的目录分离 ADR，再把稳定术语写入 `CONTEXT.md`。
5. 细化首期 schema、API、后台任务和管理端审核验收，不提前实现多来源合并。

完整契约见 `data-and-sync-contract.md`。首期 migration 编号预留为 `0040_av_catalog_core`，仅在 ADR 接受且至少一个来源获批后创建。
